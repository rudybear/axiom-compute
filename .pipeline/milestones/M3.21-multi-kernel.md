# M3.21 — Multi-kernel modules (ROADMAP FG.9)

**Status:** PROPOSED — **Architect spec r2** (revised after dual design review: optimistic
NEEDS_DISCUSSION, pessimistic NEEDS_REVISION). See r2-changelog (§17). Architecture unchanged;
surgical hardening.
**DESIGN section on merge:** §3.1.45
**AT range:** AT-2945 .. AT-2972
**Depends on:** M3.2 (`shared[T,N]` + `workgroup_barrier`), M3.20 (golden-corpus discipline)
**Blocks:** nothing on the critical path; this is the LAST substantive non-hardware-gated feature gap.

---

## 1. Thesis in two sentences

Today AXIOM-Compute compiles **exactly one `@kernel` per file** (the wall is `emit_module`'s
`TooManyKernelsInM0` guard). FG.9 lifts that so a single `.axc` file may declare **N kernels** —
the motivating case is multi-STAGE algorithms (prefix-sum: upsweep + downsweep; two-pass reduce:
partial-sums + final-reduce) that share a tuning hole (`?WG`) across stages.

**The honest v1 decision (see §3):** N kernels compile to **N separate SPIR-V modules**, one
`OpEntryPoint` each, one metadata sidecar each — NOT one module with N entry points. This reuses
the entire single-kernel codegen + runtime unchanged, and trivially preserves the M3.20
golden-corpus byte-identity discipline.

---

## 2. What already works (the pleasant surprise)

The **front end already carries N kernels**:

- `axc_parser::ast::Module { items: Vec<Spanned<Item>> }` (ast.rs:12) — `parse_module` already loops
  over top-level `@kernel` items (parser.rs:257).
- `axc_hir::HirModule { kernels: Vec<Kernel> }` (lib.rs:38) — `lower_module` already lowers **all**
  kernels into a `Vec` (lower.rs:27-337).

So lexer / parser / HIR-lowering need **zero structural change** to accept 2+ kernels. AT-2945 simply
locks in this pre-existing behavior. The single-kernel assumption lives entirely **downstream** of HIR.

---

## 3. Core decision — module-vs-modules: **N separate modules**

| Option | Verdict | Rationale |
|---|---|---|
| **A. N separate SPIR-V modules, 1 OpEntryPoint each, 1 sidecar each** | ✅ **CHOSEN v1** | `emit.rs` is deeply single-kernel (one `Builder`, one `void main()`, one `gl_GlobalInvocationID` Input var, one capability set, one interface list). Feeding it a 1-kernel `HirModule` per kernel = **ZERO codegen change**. Runtime is string-driven (survey §Runtime): each `.spv`+sidecar prepares independently → **ZERO runtime change**. Golden identity is trivial (same code path). Vulkan-friendly: prefix-sum dispatches each stage as its own pipeline anyway. |
| B. One module, N OpEntryPoints | ❌ DEFER | Requires (i) a large `emit.rs` refactor to merge N functions + shared globals + unioned capabilities + per-entry interface lists into one `Builder`, and (ii) fixing `KernelCacheKey` which does **not** hash the entry-point name (kernel_handle.rs:46-54) so two entry points sharing `(spirv, plan)` would alias in the in-process cache. No user benefit for the multi-STAGE case. |

**Seam already present:** `crates/axc-optimize/src/grid_search.rs:200` (the autotuner — **NOT** the
same-named MCP tool file `crates/axc-driver/src/mcp/tools/grid_search.rs`, whose line 200 is
unrelated) already does exactly the v1 move —
`let hir_module = HirModule { kernels: vec![resolved] }; emit_module(&hir_module, …)`. The driver's
new `compile_module_all` generalizes this one-kernel-module wrap to a loop over `hir.kernels`.

`emit_module` **keeps** its `>1 kernels` guard as an internal invariant (the driver never feeds it
>1). Only its doc-comment/message changes (`TooManyKernelsInM0` → documented as an internal
"emit_module operates on exactly one kernel; split upstream" invariant). Optional low-priority
rename to `NotExactlyOneKernel` (churn-minimizing to keep the name).

### Output naming

- **Single-kernel file, `-o out.spv`:** byte-identical to today (golden gate). Emits `out.spv` +
  `out.spv.axc.meta.json`.
- **Multi-kernel file, `-o out.spv`, no `--kernel`:** **fail closed** — `DriverError::AmbiguousKernel
  { available: [names…] }`, NO file written (never silently pick).
- **Multi-kernel file, `--kernel NAME`:** emits just that kernel to `out.spv` + sidecar
  (`entry_point == NAME`).
- **Multi-kernel file, `--all` (stem = `-o` value with any `.spv` ext stripped):** emits every kernel
  to `<stem>.<kernel>.spv` + `<stem>.<kernel>.spv.axc.meta.json`. Deterministic, one artifact pair
  per kernel. (Example: `-o build/scan.spv --all` → `build/scan.partial_reduce.spv`,
  `build/scan.final_reduce.spv` + sidecars.)

## 4. Cross-kernel `@strategy` — **per-kernel blocks, module-global name-matched sharing**

The minimal semantics that serves the prefix-sum / two-pass-reduce case, chosen from the current
machinery (survey §Autotuner):

**Key existing fact:** hole substitution is already **whole-source textual** —
`substitute_strategy_holes` (lib.rs:327-346) replaces every `?name` occurrence across the entire file.
So a `?WG` referenced in kernel A and kernel B is **already** bound to one value by a single
assignment. Sharing falls out for free at the *binding* level; the work is discovery +
conflict-checking + strip — **plus a substitution-safety fix (below), because the current textual
substitute is a proven miscompile once two hole names prefix-collide, and M3.21 is the first
milestone to make multi-hole modules first-class.**

> **⚠ CRITICAL — the prefix-collision miscompile (empirically proven by the pessimistic reviewer).**
> `substitute_strategy_holes` (lib.rs:327-346) is a raw `str::replace("?<name>", value)` iterated over
> a `BTreeMap` in **ascending** name order (lib.rs:333). `?WG` is a substring-prefix of `?WG2`
> (also `?WGX`, `?WG_TILE`, …), and ascending order replaces the **short** name **first**, corrupting
> the longer reference: source `@workgroup(?WG,1,1) shared[i32,?WG2]` with `{WG=128, WG2=64}` produces
> `@workgroup(128,1,1) shared[i32,1282]` — the second hole silently becomes `1282` (the `128` splice
> plus the orphaned `2`), **NOT** `64`. A shared array is sized wrong / a workgroup dim is wrong, with
> **no error**. This is the SAME naive-text footgun class this project already hardened twice (M3.14
> comment-decoy, M3.15 EB.3 strip — see the lexer-anchored fix at lib.rs:348-364, which fixed the
> **strip** path but left the **substitute** path naive). It MUST be closed in this milestone.

**v1 rules:**

1. **No new grammar.** Each `@kernel` may carry its own `@strategy { … }` block (existing per-kernel
   annotation). No module-level `@strategy` block in v1.
2. **Holes are keyed by NAME across the whole module** (a single module-global namespace). The
   autotuner enumerates over the **union** of distinct hole names across all kernels' `@strategy`
   blocks.
3. **Shared = same name.** A hole name declared (with a candidate list) in ≥2 `@strategy` blocks
   **MUST** have byte-identical candidate lists, else **fail closed** with
   `ConflictingHoleCandidates { name }`. This makes "shared" unambiguous.
4. A `?name` **referenced** in one kernel but **declared** in another kernel's `@strategy` block is
   valid (that's the sharing). One resolved value substitutes into all references module-wide.
5. **Independent per-kernel tuning still works** via distinct names → distinct Cartesian axes.
6. **The winner assignment applies module-wide**; every kernel compiles with the same resolved
   values.

**Implementation contract (the required behavioral fixes):**

- **F1 — boundary-safe hole substitution (CRITICAL, closes the prefix-collision miscompile).**
  Rewrite the Pass-1 loop of `substitute_strategy_holes` (lib.rs:331-337) so a `?name` is replaced
  **only when the byte immediately following the matched name is not an identifier-continuation char**
  `[A-Za-z0-9_]` (and, symmetrically, treat the leading `?` as the left boundary — a `?` is not an
  identifier char, so no left-guard beyond matching the literal `?name` is needed).

  **Exact mechanism (the SOUND one — not a bandaid):** a **manual single left-to-right scan** of the
  source (regex-free, to avoid a new dep and to stay allocation-lean): walk byte offsets; at each `?`,
  greedily match the **longest** hole name from the assignment set that occurs at that position
  **AND** whose following byte ∉ `[A-Za-z0-9_]`; if matched, emit the replacement and advance past the
  name; else copy the byte. The **following-byte boundary check is the correctness guarantee**;
  longest-name-first matching is added as belt-and-suspenders (it makes the scan pick `?WG2` over
  `?WG` when both are candidates at the same offset) but **must not be relied on alone** — the
  boundary check is what makes `?WG` followed by `2` refuse to match `WG`. A single forward scan also
  removes the ascending-BTreeMap ordering hazard entirely (each source position is decided once).

  This same fix protects **every** caller of `substitute_strategy_holes`, notably rewrite-verify's
  `compile_source_with_assignments` path, not just the new multi-kernel autotuner.

  **Comment-scope decision (stated honestly):** the raw `str::replace` today **also** substitutes
  `?name` occurrences inside `//` comments (pre-existing behavior; the substitute path is NOT
  lexer-anchored, unlike the strip path). The boundary fix operates on raw text and **deliberately
  does NOT add comment-awareness** — a `?WG` sitting in a comment will still be rewritten to its value.
  **Rationale for deferring comment-awareness (not fixing it here):** a substitution inside a comment
  is **semantically harmless** — the lexer discards comments before HIR, so a comment reading
  `// tuned ?WG` becoming `// tuned 128` cannot change compiled SPIR-V, hole resolution, or the golden
  bytes. The danger the boundary fix closes (a silent *miscompile* via prefix collision) lives only in
  **live** code, where a comment cannot reach. So: F1 makes the substitute path **prefix-safe** but
  **not** comment-aware, and that asymmetry is correct — comments can't miscompile. (Contrast the
  **strip** path, where a comment decoy *could* remove the wrong block, which is exactly why that path
  *was* lexer-anchored. The two paths have different failure modes and correctly get different guards.)
  AT-2968 pins both the prefix-safety and this comment behavior.

  **Defense-in-depth (second layer, cheap):** `union_module_holes` additionally rejects a module whose
  resolved hole-name set contains a name that is a **prefix of another** hole name, emitting
  `EnumerateError::PrefixCollidingHoleNames { shorter, longer }`. F1 already makes substitution
  correct even for prefix-colliding names, so this is not required for soundness — but it fails
  *closed and loudly* at discovery time on an ambiguous authoring pattern rather than silently
  producing a technically-correct-but-confusing rewrite, and it costs ~10 LOC. Both layers ship.

- **F2 — strip ALL blocks.** `strip_strategy_annotation_block` (lib.rs:365, strips only the FIRST
  block) → add `strip_all_strategy_annotation_blocks` that loops the existing lexer-anchored strip.
  **Termination predicate (pessimistic WARNING):** loop **while the last strip actually changed the
  source** (`prev != next`), NOT "while a `@strategy` token exists" — the underlying strip returns the
  source **unchanged** for the call-form `@strategy(...)` (lib.rs:395-398), so a token-existence
  predicate would **infinite-loop** on a residual call-form annotation. Keying on "a change occurred"
  terminates on the first no-op. Required because a 2-kernel file has 2 brace-form blocks and a
  residual block would trip the codegen `UnresolvedStrategyHole` backstop.

- **F3 — module-global hole discovery.** Hole discovery in `run_optimize` (optimize.rs:69,
  `kernels.first()`), MCP `enumerate_variants` (:80), MCP `grid_search` (:443), MCP `load_source`
  (:120) → replace "pick kernel[0]" with `union_module_holes` (union across all kernels +
  conflict-check + prefix-collision check).

- **F4 — winner must be valid MODULE-WIDE (pessimistic WARNING, closes AT-2957's unenforced claim).**
  The grid search benches only the `--kernel` target and compiles only that kernel per variant, so a
  winning `?WG` value is never checked against the **sibling** kernels during the search — a winner
  could make a non-benched kernel overflow its shared-memory budget or emit invalid SPIR-V yet still
  be crowned. **Before writing the winner sidecar**, `run_optimize` MUST cross-compile the winning
  assignment across **ALL** kernels via `compile_module_all` (on the substituted+stripped source) and
  **fail closed** — surfacing which sibling broke — if any sibling fails to compile/validate. AT-2970
  gates this with a candidate that is valid for the benched kernel but invalid for a sibling.

**Autotuner bench scope (v1):** grid-search's `bench_fn` times **one** dispatched kernel. v1 requires
`--kernel NAME` to name the timing target; the shared hole still binds module-wide so the benched
kernel gets consistent values, and F4 re-validates the winner across every kernel before it is
written. **DEFER:** a joint multi-stage bench that times stage1+stage2 as a pipeline.

> **Spec note (durable, project-wide) — naive-text transforms are a recurring footgun.** This is the
> **THIRD** instance of an un-boundaried text transform on structured tokens (M3.14 comment decoy →
> lexer-anchored find; M3.15 EB.3 strip → lexer-anchored strip; M3.21 F1 substitute → boundary-safe
> scan). **Any future source-text transform that acts on `?holes`, `@annotations`, or identifiers MUST
> be token/boundary-disciplined** (lexer-anchored or following-byte-guarded), never a raw
> `str::find`/`str::replace`. Reviewers should treat a bare `.replace("?"...)` or `.find("@"...)` on
> live source as a defect on sight.

## 6. The example — `two_pass_reduce.axc` (bit-exact, two-stage, shared hole)

**Chosen over full Blelloch prefix-sum** (which needs a downsweep with per-element output — more
barriers, more risk) as the simplest honest artifact that proves ALL of FG.9: N kernels/file,
sequential multi-stage GPU dispatch, a cross-kernel shared `@strategy` hole, and bit-exact vs a CPU
oracle.

**Integer sum reduction (i32 — associative, so bit-exact by construction regardless of grouping;
`is_allowed_shared_element(I32) == true`, shared.rs:125). This sidesteps the entire f32-reassociation
surface that the M3.x campaign wrestled with.**

- `@kernel partial_reduce(input: readonly_buffer[i32], partials: buffer[i32], n: u32)` —
  `@workgroup(?WG,1,1)`, `shared partial: shared[i32, ?WG]`. Each workgroup reduces its `?WG`-element
  chunk to one partial: `tile[lid] = input[wg*?WG + lid]; workgroup_barrier();` then a
  **workgroup-uniform** tree reduction; lane 0 writes `partials[wg]`.
- `@kernel final_reduce(partials: readonly_buffer[i32], out: buffer[i32], n_parts: u32)` —
  `@workgroup(?WG,1,1)`, `shared acc: shared[i32, ?WG]`. A single workgroup reduces the `n_parts`
  partials to `out[0]`.
- **Shared hole `?WG` ∈ {64, 128, 256}** referenced in BOTH kernels' `@workgroup(?WG,1,1)` AND both
  `shared[i32, ?WG]` — the cross-kernel binding.

**GPU test (anti-pattern #9):** dispatch stage1 (grid = `n/?WG` workgroups) → stage2 (1 workgroup)
**in sequence** on real GPU. `out[0] == Σ input` exactly (integer add) → `max_diff == 0` on NVIDIA
(`AXC_ENABLE_GPU_TESTS=1`) AND Lavapipe (CI fallback). Fixed `n = 4096` with the default `?WG` so
`n_parts == n/?WG ≤ 256 ≤ ?WG` (stage2's single workgroup covers all partials).

### 6.1 PRIMARY TECHNICAL RISK — barrier-in-loop for the hole-parameterized reduction

A `?WG`-parameterized reduction depth requires a **`while stride > 0u32` loop** with the
`workgroup_barrier()` at loop-body top level (unconditional, **workgroup-uniform** control flow — all
invocations share `stride`) and the accumulating add guarded by `if lid < stride { … }` (the barrier
is OUTSIDE the `if`). This must pass:

- **OQ1** (M3.2 SET-based missing-barrier-before-cross-invocation-read analysis), and
- **OQ2** (M3.2 divergent-barrier hard error — the barrier is in uniform, not divergent, context).

**FALLBACK if the looped form trips either analysis:** pin `?WG` to a **single** candidate (e.g.
{64}) and fully unroll the 6-level tree reduction straight-line, mirroring the proven
`shared_reduce.axc` barrier structure. The cross-kernel hole BINDING is still demonstrated at compile
time (`shared[i32,?WG]` + `@workgroup(?WG,1,1)` textual substitution into both kernels; AT-2956), just
with a degenerate one-candidate search. **The Coder resolves the looped-vs-unrolled form against the
real OQ1/OQ2 analyzers; either satisfies the milestone.**

## 7. Golden identity (M3.20 discipline)

**All 54 existing single-kernel `examples/*.axc` must compile byte-identical** (both `.spv` and
sidecar JSON) through the new path. Because `compile_module_all` on a 1-kernel file wraps the single
kernel in `HirModule{kernels: vec![k]}` and runs the unchanged `emit_module` + unchanged metadata
build, output is byte-for-byte the pre-M3.21 result. AT-2947 (per-kernel golden equivalence to the
old `compile_source_with_meta`) + AT-2948 (whole-corpus, all 54) gate this.

## 8. Public API (signatures — no implementation)

```rust
// crates/axc-driver/src/lib.rs

/// One compiled kernel from a (possibly multi-kernel) module.
pub struct CompiledKernel {
    pub name: String,          // == entry_point == metadata.kernel_name
    pub spirv: Vec<u8>,
    pub metadata: KernelMetadata,
}

/// Compile EVERY @kernel in the source to its own SPIR-V module + metadata.
/// Iterates hir.kernels; wraps each as a 1-kernel HirModule; reuses emit + metadata.
/// Empty module → DriverError::Compile (no kernels, unchanged).
pub fn compile_module_all(source: &str, debug_checks: bool)
    -> Result<Vec<CompiledKernel>, DriverError>;

/// Select ONE kernel by name (or the sole kernel if exactly one and `kernel==None`).
/// `None` + >1 kernel → DriverError::AmbiguousKernel.
/// `Some(name)` not found → DriverError::UnknownKernel.
///
/// **WRONG-METADATA GUARD (§5):** this fn MUST build a SINGLE 1-kernel module
/// `let one = HirModule { kernels: vec![selected.clone()] };` and thread THAT SAME
/// `one` through BOTH `emit_module_bytes(&one, …)` AND the metadata block
/// (`extract_workgroup_dims(&one)`, `one.kernels.first()`, shared-bytes, coopmat).
/// It MUST NOT feed a filtered module to emit while building metadata from the
/// original multi-kernel HIR — that would pair a non-first kernel's SPIR-V with
/// kernel[0]'s workgroup_size/name. AT-2969 gates this with distinct per-kernel dims.
pub fn compile_source_with_meta_kernel(
    source: &str,
    kernel: Option<&str>,
    debug_checks: bool,
) -> Result<(Vec<u8>, KernelMetadata), DriverError>;

// compile_source_with_meta[_debug] keep their signatures and delegate to
// compile_source_with_meta_kernel(source, None, …) — unchanged for single-kernel callers.

// New DriverError variants:
//   AmbiguousKernel { available: Vec<String> }
//   UnknownKernel   { name: String, available: Vec<String> }

/// Strip ALL @strategy { … } blocks. Loops the lexer-anchored
/// strip_strategy_annotation_block WHILE it keeps changing the source
/// (`prev != next`) — NOT while a @strategy token exists (the call-form
/// @strategy(...) is a strip no-op and a token-existence loop would hang). F2.
pub(crate) fn strip_all_strategy_annotation_blocks(source: &str) -> String;

// substitute_strategy_holes (lib.rs:327) — F1 hardening: Pass-1 becomes a single
// left-to-right boundary-safe scan. A `?name` substitutes ONLY when the byte after
// the matched name ∉ [A-Za-z0-9_]; longest-name-first at a given `?` as a tiebreak.
// Signature unchanged; behavior made prefix-collision-safe. (Not comment-aware — see §4.)
```

```rust
// crates/axc-optimize/src/enumerator.rs (module-global hole discovery helper)

/// Union the @strategy hole maps across all kernels of a module.
/// - Same name with differing candidate lists → EnumerateError::ConflictingHoleCandidates { name }.
/// - Any hole name that is a PREFIX of another hole name (e.g. ?WG vs ?WG2) →
///   EnumerateError::PrefixCollidingHoleNames { shorter, longer } (F1 defense-in-depth:
///   fails closed on the ambiguous authoring pattern at discovery time; substitution
///   is already correct thanks to F1, this just refuses to be confusing).
pub fn union_module_holes(module: &HirModule)
    -> Result<StrategyHoles, EnumerateError>;
```

`Optimize { …, kernel: Option<String> }`; `RewriteVerify { …, kernel: Option<String> }`;

## 13. Edge cases

- **Empty file (0 kernels):** `compile_module_all` → `DriverError::Compile` (unchanged NoKernels path); CLI errors, no file written.
- **Multi-kernel + `-o` + no `--kernel` + no `--all`:** `AmbiguousKernel { available }`, exit ≠ 0, **no partial output**.
- **`--kernel NAME` not found:** `UnknownKernel { name, available }`.
- **`--kernel` AND `--all` both given:** clap `conflicts_with` → usage error.
- **Duplicate kernel names in one file:** must fail closed (would collide on output path + entry point) — `DuplicateKernelName { name }`. (HIR/parser do not reject this today; add the check.)
- **Shared hole `?WG` declared in two blocks with different candidate lists:** `ConflictingHoleCandidates { name }`.
- **Prefix-colliding hole names (`?WG` and `?WG2`) in one module:** substitution is boundary-safe (F1, AT-2968); discovery additionally fails closed `PrefixCollidingHoleNames { shorter, longer }` (AT-2972). Neither can produce the `1282` miscompile.
- **`?WG` inside a `//` comment:** F1 may still substitute it (harmless — lexer discards comments; cannot change compiled bytes or hole resolution). Comment-awareness of the SUBSTITUTE path is deferred with rationale (§4); the STRIP path is already lexer-anchored/comment-safe.
- **`?name` referenced but never declared in any `@strategy`:** existing `UnresolvedStrategyHole` backstop still fires (unchanged).
- **`two_pass_reduce.axc` (2 `@strategy {` blocks) vs the at_2835 corpus anchor:** the anchor's residual clause branches on block count (strip-all for >1-block files); the naive-reference equality clause is unchanged for single-block files (AT-2971).
- **Grid-search winner valid for the benched kernel but invalid for a sibling:** F4 cross-compiles the winner across ALL kernels before the sidecar write and fails closed naming the sibling (AT-2970).
- **Second `@strategy` block left unstripped (regression guard):** AT-2955 asserts `strip_all_…` (change-predicate loop) removes every brace-form block; a residual `@strategy(...)` call-form is a strip no-op and terminates the loop rather than hanging.
- **Single-kernel file through every touched surface:** byte-identical / behavior-identical (golden + regression).
- **`n` not a multiple of `?WG`** in the example: fixed `n=4096` and constrained candidate set avoid partial tiles (edge-tile handling is out of scope, mirrors M3.3b).

1. **CRITICAL — prefix-collision miscompile (F1).** §4 now mandates a **boundary-safe**
   `substitute_strategy_holes`: a **single left-to-right scan** that replaces `?name` only when the

   rationale (contrast the STRIP path, which IS lexer-anchored because a comment decoy there removes the
