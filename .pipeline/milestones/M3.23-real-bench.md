## 0. Motivation

The M4.2a pessimistic design review surfaced a pre-existing **M2.3 gap**: `run_optimize`
(`crates/axc-driver/src/optimize.rs:127-144`) resolves `@strategy` holes and picks a
"winner" using a **MOCK bench** — a closure that returns a fixed `1000 ns` for *every*
variant with `correctness_fn = None`. It **never dispatches** and **never checks
correctness**. The `axc optimize` CLI therefore emits a winner that is not measured and
not verified — a silent fake.

Meanwhile the MCP `grid_search` path already benches for real: its per-variant
`bench_variant::handle` (`crates/axc-driver/src/mcp/tools/bench_variant.rs`) does a real
prepare + dispatch and applies a **tri-state device-keyed correctness oracle**
(`pick_cpu_reference` → `check_correctness`, `Ok | Failed | NotChecked`). And every M3.x
TFLOPS bench (`crates/axc-driver/benches/resident_*.rs`) times kernels via the runtime's
**GpuTimestamp MIN-of-N resident harness** (`upload_resident` / `dispatch_resident` /
`readback_resident`).

**M3.23 wires the real thing into `run_optimize` by reusing that existing machinery**, and
folds in the cheap polish rows that are genuinely ≤ ~50–100 LOC each. It is deliberately a
reuse-and-glue milestone: no new correctness math, no new timing primitive, no compiler
change.

## 1. Part A — the real bench for `run_optimize`

### 1.1 Design in one paragraph

Keep the existing `run_optimize` structure — module-global hole union (F3), the library
`axc_optimize::grid_search::grid_search` driver, and the F4 winner cross-validation.
**Replace the mock `bench_fn` with a real GpuTimestamp MIN-of-N closure and pass a real
`correctness_fn`.** Both closures are built once from the bench-target kernel's *invariant*
metadata plus a `VulkanContext`. GPU-less callers fail closed with a typed error (no fake
winner). The sidecar stays the same `GridSearchResult` type; a `NotChecked` oracle result
is surfaced as a `warnings` entry (no schema change).

### 1.2 Signature change

```rust
pub fn run_optimize(
    input: &Path,
    output: &Path,
    correctness_str: &str,
    kernel: Option<&str>,
    vk: Option<&axc_runtime::VulkanContext>,   // NEW
) -> Result<(), OptimizeError>
```

The `vk` param is consumed at a **pinned position** inside `run_optimize` — see §1.3.1
(after the cheap CPU-only diagnostics, before `grid_search`).

`main.rs` wires `vk` with the **same pattern** used by the `fuzz`/`bench` commands
(`main.rs:375-379`, `main.rs:499`):

```rust
Command::Optimize { input, output, correctness, kernel } => {
    let vk = if axc_runtime::probe_vulkan_available() {
        axc_runtime::VulkanContext::new().ok()
    } else { None };
    run_optimize(&input, &output, &correctness, kernel.as_deref(), vk.as_ref())
        .map_err(|e| miette::miette!("{}", e))
```

### 1.3 GPU-less behaviour — FAIL CLOSED (honest preservation)

**Today's behaviour class:** the mock never touches Vulkan, so `run_optimize` *always
completes* headless — but the winner it emits is fake. The behaviour worth preserving is
**honesty**, not "always completes". A real bench cannot run without a GPU, so the honest
outcome is to **fail closed** rather than fall back to a fake winner:

- `vk == None` ⇒ return `OptimizeError::GpuUnavailable` **before any artifact is written**
  (zero `.spv`, zero sidecar — consistent with the F4 "no orphans" discipline).

New error variant:

```rust
#[error("GPU unavailable: `axc optimize` requires a Vulkan device to bench variants \
         (no fake/mock winner is emitted); {0}")]
GpuUnavailable(String),
```

On CI **with Lavapipe** the probe succeeds, so the real path runs on the software GPU;
coopmat kernels then fail **per variant** at the UNCHECKED `prepare_kernel` boundary — the
closures call plain `vk.prepare_kernel(...)` (mirroring `bench_variant.rs:279`), NOT
`prepare_kernel_checked`, so the driver rejects the unsupported-capability SPIR-V with a
`ShaderModuleCreationFailed`/`PipelineCreationFailed`-class `DispatchError` (`pipeline.rs:63/173`),
**not** the preflight `CoopMatUnsupported`/`DeviceFeatureUnsupported` variants (those are emitted
only by `preflight_kernel_support`, invoked solely from `prepare_kernel_checked`, `context.rs:1576`).
Any such `Err` maps to `BenchOutcome::Failed`, and the library's R3 fallback chain selects
ordinal 0 with `fallback_used = true` — the sidecar records every variant's real failure reason.
Simple kernels (e.g. the shared-len-hole copy fixture) run to real timings on Lavapipe.

### 1.3.1 vk==None check ORDERING (pinned — do NOT hoist to the top)

The `vk.is_none()` fail-closed check **MUST** be placed AFTER the cheap CPU-only diagnostics
and BEFORE `grid_search`, in exactly this order (matching `run_optimize`'s existing structure,
`optimize.rs:81-114`):

```
parse (lex/parse errors)      → OptimizeError::Compile      (optimize.rs:87-102)
  ↓
union_module_holes / empty    → OptimizeError::NoStrategy   (optimize.rs:107-110)
  ↓
select_kernel(kernel)         → OptimizeError::Compile(AmbiguousKernel)  (optimize.rs:113-114)
  ↓
>>> if vk.is_none() { return Err(GpuUnavailable) }   <<< INSERT HERE, before bench_kernel/grid_search
  ↓
grid_search (real bench)      → winner
  ↓
cross_validate_winner_module_wide (F4) → write artifacts
```

Rationale: a headless user gets the *useful* diagnostic — a parse error, a "no `@strategy`
holes" (`NoStrategy`), or an `AmbiguousKernel` "you must pass `--kernel`" — rather than the
blunt `GpuUnavailable`, which only fires once the request is otherwise well-formed and a real
bench is genuinely unavoidable. This preserves the two existing headless fail-closed tests
(`optimize_no_kernel_on_ambiguous_source_fails_closed` → `AmbiguousKernel`; any `NoStrategy`
path) unchanged; only the well-formed happy path degrades to `GpuUnavailable` headless.

### 1.4 The reuse map (precise — which functions, what glue)

**Metadata (invariant across `@strategy` variants — holes are integer knobs on shared/tile
sizes, never the buffer signature or push-constant layout):** taken once from the selected
kernel, no extra compile needed.

| Need | Source |
|---|---|
| binding plan (buffers + scalars + `push_constant_total_bytes`) | `selected.binding_plan` |
| entry point | `selected.name` |
| workgroup size `[u32;3]` | `selected.annotations.workgroup.{x,y,z}` |
| oracle key | `selected.name` (via `pick_cpu_reference`) |
| device name (device-keyed ULP) | `vk.physical_device_name()` |

**Inputs / geometry — reused verbatim from `bench_variant`:**
- `bench_variant::seeded_inputs(&input_sizes, SEED)` with a **fixed** `SEED = 0` (all variants
  see identical inputs ⇒ fair timing + comparable outputs for the oracle).
- `bench_variant::derive_workgroups(&input_sizes, workgroup_size, None)`.
- `input_sizes`: default `vec![DEFAULT_BENCH_BYTES; plan.buffers.len()]`
  (`DEFAULT_BENCH_BYTES = 4096`, matching the MCP `grid_search` default at
  `mcp/tools/grid_search.rs:296-299`).
- push constants: zero-filled `vec![0u8; push_constant_total_bytes]` (bench_variant's own
  default; `build_push_constants`, `bench_variant.rs:344-366`).
  **Documented limitation — BOTH the correctness AND the timing/winner-integrity face
  (the M3.18 alpha=0 lesson, timing side):**
  - *Correctness:* a kernel whose correctness depends on non-zero scalar args (e.g. a
    matmul's `M/N/K`) is dispatched at a degenerate shape; its oracle is `NotChecked` unless
    registered.
  - *Winner integrity (NEW disclosure):* a kernel whose **work** is gated on a scalar push
    constant — e.g. `let n = pc.n; if n == 0u32 { return; }`, or a K-loop `for k in 0..pc.K` —
    measures a **no-op degenerate kernel** under all-zero push constants, so a variant can
    "win" by doing nothing. Its timing (and therefore its winner) is **not meaningful** for
    scalar-gated kernels until the deferred `--push-constants` surface lands.
  - *Why not just random-seed the scalars?* Unlike buffers, push constants **cannot** be
    blindly random-filled: a random `u32` loop bound ≈ 4×10⁹ → hang / OOB. That is exactly
    why the reused machinery zero-fills. The honest fix is **disclosure, not seeding**.
  - *Cheap reuse that IS available:* where a scalar is a **buffer-length** count, the
    registered-oracle path already substitutes the buffer's element count for it (see the
    saxpy note, `bench_variant.rs:474/492`: "we use buffer length as `n` here"). That reuse
    is **oracle-local** (baked into `pick_cpu_reference`'s registered CPU references) and does
    **not** generalize to arbitrary scalar-gated kernels — there is no general fuzz-satisfier
    that derives size-coupled scalars from buffer sizes to reuse. So: buffer-length-derived
    `n` is already correct for the registered oracles; every other scalar-gated kernel is a
    **documented limitation** (no-work timing) until `--push-constants`.
  - A caller-supplied push-constant / input-size surface is out of scope (future
    `axc optimize --input-sizes/--push-constants`).

**Timing — the resident GpuTimestamp MIN-of-N harness (same as every `resident_*.rs` bench):**
`VulkanContext::{prepare_kernel, upload_resident, dispatch_resident}` with
`ResidentBenchConfig`, `N_WARMUP = 2`, `N_MEASURED = 10`, statistic = **MIN** of
`kernel_ns`. This is a deliberate refinement over `bench_variant`, which times with
CPU-wall `Instant::now()` (scheduling-inclusive) — `run_optimize` uses the honest GPU
kernel-time path the roadmap standardises on. `timing_source` (`GpuTimestamp` vs
`CpuFenceWall` on Lavapipe) is captured and disclosed on stderr, never presented as a GPU
time when it is not one.

**Correctness — `bench_variant`'s tri-state device-keyed oracle (verbatim):**
`bench_variant::{pick_cpu_reference, check_correctness}` (device-keyed via
`ulp_tolerance_for_device`; the FROZEN `within_ulp_f32` is untouched).

### 1.5 The two closures (glue)

```rust
// policy != None ⇒ library calls this BEFORE bench_fn for each variant.
// TWO faces now run per variant (§1.5.1): (1) the ALWAYS-ON variant-vs-variant
// differential (DETECTS divergence), (2) the registered CPU oracle when present
// (ATTRIBUTES — the only thing that can say WHICH side is wrong). `ord` is the
// per-call ordinal (Cell counter, incremented at entry).
let correctness_fn = &|words: &[u32]| -> Result<(), CorrectnessFailure> {
    let ord = ordinal.get(); ordinal.set(ord + 1);
    let handle = vk.prepare_kernel(words, plan, pc_bytes, entry)
        .map_err(|e| CorrectnessFailure::OracleError(e.to_string()))?;
    let resident = vk.upload_resident(&handle, &input_refs, &output_sizes_u64)
        .map_err(|e| CorrectnessFailure::OracleError(e.to_string()))?;
    let _ = vk.dispatch_resident(&handle, &resident, &cfg)
        .map_err(|e| CorrectnessFailure::OracleError(e.to_string()))?;
    let outputs = vk.readback_resident(&handle, &resident, &output_sizes_u64)
        .map_err(|e| CorrectnessFailure::OracleError(e.to_string()))?;

    // (1) DIFFERENTIAL (ALWAYS applies when policy != None) — DETECT-ONLY (§1.5.1).
    // First validated variant establishes the reference; each later variant is
    // compared against it. A mismatch means the variants DISAGREE — but the
    // differential CANNOT know which side is correct (the reference is just the
    // first-seen output, NOT ground truth). So on mismatch we RECORD the divergent
    // pair and defer the verdict; attribution (if any) comes from the oracle below.
    match reference_outputs.borrow().as_ref() {
        None => { /* first variant: fall through, seed reference below */ }
        Some(reference) => {
            // differential_mismatch does a BITWISE blob-equality fast-path FIRST
            // (bit-equal ⇒ match, done); only bit-INequal blobs fall through to the
            // f32-ULP compare (§1.6) — so two distinct garbage NaN-patterns can never
            // NaN-collapse into a false "match".
            if let Some((_count, _max_ulp)) =
                differential_mismatch(reference, &outputs, ulp_tol)
            {
                // DETECTED divergence. Record (reference_ord, ord). Do NOT reject
                // `ord` here on the basis of the differential alone — that would
                // presume the reference is correct. run_optimize decides after
                // grid_search: unattributable ⇒ VariantsDiverge run-error (§1.5.1).
                divergence.borrow_mut().get_or_insert_with(Vec::new)
                    .extend_from_slice(&[reference_ord.get(), ord]);
                // fall through to the oracle: if it is registered it will attribute.
            }
        }
    }

    // (2) ORACLE (ATTRIBUTION — only when a CPU reference is registered).
    let oracle = bench_variant::check_correctness(
        kernel_name, plan, &input_data, Some(&outputs), &EMPTY_ASSIGN, &device_name,
    );
    match oracle {
        // A real ground-truth verdict ran ⇒ attribution is AVAILABLE for this run.
        CorrectnessStatus::Ok => { oracle_attributed.set(true); }
        CorrectnessStatus::Failed { reason } => {
            oracle_attributed.set(true);
            return Err(CorrectnessFailure::OracleError(reason)); // oracle rejects the wrong variant
        }
        // No absolute ground truth (unregistered, or a binding-shape mismatch):
        // attribution is NOT available from the oracle for this variant.
        CorrectnessStatus::NotChecked { .. } => { saw_not_checked.set(true); }
    }

    // Seed the reference from the FIRST variant that reaches here (its ordinal too).
    if reference_outputs.borrow().is_none() {
        *reference_outputs.borrow_mut() = Some(outputs); // keep exactly ONE reference copy
        reference_ord.set(ord);
    }
    Ok(())
};

let bench_fn = &|words: &[u32]| -> Result<SampleStats, String> {
    let handle = vk.prepare_kernel(words, plan, pc_bytes, entry).map_err(|e| e.to_string())?;
    let resident = vk.upload_resident(&handle, &input_refs, &output_sizes_u64).map_err(|e| e.to_string())?;
    for _ in 0..N_WARMUP { vk.dispatch_resident(&handle, &resident, &cfg).map_err(|e| e.to_string())?; }
    let (mut min_ns, mut max_ns) = (u64::MAX, 0u64);
    for _ in 0..N_MEASURED {
        let t = vk.dispatch_resident(&handle, &resident, &cfg).map_err(|e| e.to_string())?;
        min_ns = min_ns.min(t.kernel_ns); max_ns = max_ns.max(t.kernel_ns);
        last_timing_source.set(t.timing_source);
    }
    Ok(SampleStats { median_ns: min_ns, min_ns, max_ns, n_samples: N_MEASURED }) // MIN is the reported metric
};
```

- `EMPTY_ASSIGN`: `check_correctness`'s `_assignments` param is unused today — an empty map.
- `saw_not_checked` / `last_timing_source` / `oracle_attributed` / `ordinal` / `reference_ord`:
  `std::cell::Cell<_>` captured by the closures; read after `grid_search` returns.
  (`ordinal` is a per-call counter; `reference_ord` records the ordinal that seeded the
  reference; `oracle_attributed` is set true the moment `check_correctness` returns a real
  `Ok`/`Failed` verdict — i.e. attribution actually ran.)
- `reference_outputs`: `std::cell::RefCell<Option<Vec<Vec<u8>>>>` captured by `correctness_fn`;
  holds exactly ONE variant's readback (the differential reference — §1.5.1).
- `divergence`: `std::cell::RefCell<Option<Vec<usize>>>` — the ordinals of any variants that
  disagreed with the reference (read after `grid_search`; drives the `VariantsDiverge`
  run-error when attribution is unavailable — §1.5.1).
- `ulp_tol`: `bench_variant::ulp_tolerance_for_device(&device_name)` — the SAME device-keyed
  tolerance (4 real HW / 8 llvmpipe) the registered oracle uses; computed once.
- `policy == None` (the common pure-perf case) ⇒ the library never calls `correctness_fn`,
  so each variant dispatches once (bench only) — no double dispatch, and **no differential**
  (the differential lives inside `correctness_fn`; a pure-perf run opts out of readback by
  construction).

### 1.5.1 The variant-vs-variant differential (DETECT divergence; REFUSE to crown without attribution)

**Problem it closes (the mandate's core failure mode).** For the overwhelmingly common case
where `pick_cpu_reference` returns `None` (only `saxpy`/`vector_add`/`q4_0_dequant_matvec` are
registered — every real optimize target is *unoracled*), r1's "proceed on `NotChecked`" left
the tuner picking the fastest variant with **no per-variant correctness signal**. A tile-size
`@strategy` variant that drops a barrier or introduces a race is frequently *faster* (races
skip synchronization) and would **win** — shipped as the winner `.spv` with only a generic
`NotChecked` warning. This is precisely the silent-wrong-winner the roadmap's honesty
discipline exists to prevent.

**What the differential can and cannot do (the r3 correction — reference-attribution blind
spot).** Every `@strategy` variant is the **same kernel** with different perf knobs. On
identical seeded input (`SEED = 0`, §1.4) they **must** produce identical output, so a
disagreement between two variants is a *real signal that at least one is wrong*. **But the
differential only detects DISAGREEMENT; it cannot ATTRIBUTE it.** The reference is merely the
first variant's readback — **not ground truth**. r2 rejected the *later* (non-reference)
variant on mismatch, which silently presumes the reference (ordinal 0) is the correct one. If
**ordinal 0 is the garbage variant** (e.g. it is the fast-but-racy one and it benched first),
r2 would `CorrectnessRejected` the *correct majority* and crown the garbage — **worse** than a
blanket proceed. The differential is therefore a **detector, not an attributor**. (This
corrects the r2 §1.5.1 overclaim "prevents fast-garbage winning": it **detects divergence and
refuses to crown without attribution** — it does not, on its own, identify the good variant.)

**The r3 semantics — fail-closed on unattributable divergence.** Under `policy != None`:

- The first variant that reaches the oracle seeds `reference_outputs` and `reference_ord`
  (memory cost: **one** reference copy — a few KB at the 4 KB/buffer default).
- Every subsequent variant's readback is compared against the reference by
  `differential_mismatch` (bitwise fast-path then f32-ULP; §1.6). A mismatch is **recorded**
  in the `divergence` ordinal set — the variant is **NOT** rejected on the differential's word
  alone (that would presume the reference is correct).
- **Attribution comes ONLY from a registered oracle.** `check_correctness` returning a real
  `Ok`/`Failed` verdict sets `oracle_attributed = true`; a `Failed` variant is rejected on the
  oracle's ground truth (the correct attribution — the oracle knows which output is right,
  independent of ordinal).
- **After `grid_search`, in `run_optimize` (the decision point):**
  - `divergence` non-empty **AND** `!oracle_attributed` ⇒ divergence was detected but nothing
    could say which side is correct ⇒ **`return Err(OptimizeError::VariantsDiverge { ordinals })`
    with ZERO artifacts** (no `.spv`, no sidecar). We refuse to crown ANYONE: divergence
    detected, attribution impossible. This is **direction-independent** — it fires the same
    whether the garbage variant seeded the reference (ordinal 0) or diverged from it (later
    ordinal), because we never trust the reference as truth.
  - `divergence` non-empty **AND** `oracle_attributed` ⇒ the oracle already rejected the wrong
    variant(s); the agreeing-and-oracle-`Ok` variants remain eligible ⇒ proceed to F4 + write.
  - `divergence` empty ⇒ all variants agreed (the healthy common case) ⇒ proceed; fastest wins.

New error variant (fail-closed, before any write — same discipline as `GpuUnavailable`):

```rust
#[error("variants diverged with no ground-truth oracle to attribute correctness: \
         ordinals {0:?} produced different output on identical seeded input; \
         refusing to crown a winner (register a CPU reference for kernel `{1}` to disambiguate)")]
VariantsDiverge { ordinals: Vec<usize>, kernel: String },
```

- `differential_mismatch(reference, outputs, ulp_tol)` reuses `correctness_match` /
  `within_ulp_f32` (FROZEN, untouched) for the f32 leg, **behind a bitwise fast-path** (§1.6).
  The ULP tolerance absorbs *legitimate* reduction-order rounding (a tile/WG change can reorder
  an f32 reduction) while catching gross divergence (races, uninitialised/garbage output).
  **Limitation (documented):** for a non-`f32` output buffer the `f32` reinterpretation is an
  approximation; the `binding_plan` carries each buffer's element type if a future refinement
  wants exact per-type comparison — out of scope here (the registered oracles and the M3.22
  fixtures are all `f32`/`u32`-copy, where the fast-path makes a copy bit-identical and the ULP
  leg is exact-via-ULP for f32).

**What this buys (honest framing).** The differential **cannot** silently ship a wrong winner
under `NotChecked`: the *only* outcomes are (a) all variants agree → a real winner, (b)
variants disagree with an oracle to attribute → oracle-attributed winner, (c) variants disagree
with no oracle → **hard error, no artifacts**. The fast-but-racy variant can never be crowned;
in case (c) *nobody* is, which is the correct fail-closed posture when correctness is
undecidable. `NotChecked` in the sidecar (case a) now honestly means "variants agreed with each
other, but no absolute oracle confirmed the shared answer" — the §1.5 warning text says exactly
that.

**Winner semantics.** Unchanged from the library: fastest `median_ns` (== MIN) wins; ties
break by ordinal; R3 fallback (ordinal 0→1→2→3) when nothing benches. `resolve_single_variant`
already substitutes `shared[T,?WG]` len-holes (M3.22), so the winner `.spv`'s `OpTypeArray`
length reflects the winning assignment — the winner-consistency invariant holds.

**`NotChecked` surfacing.** After `grid_search`, if `saw_not_checked.get()` **and** the run was
NOT errored as `VariantsDiverge`, push `"correctness policy requested but no CPU ground-truth \
oracle is registered for kernel `<name>`; all benched variants AGREED with each other via the \
variant-vs-variant differential (within <ulp_tol> ULP) on identical seeded input, but the \
shared answer was NOT confirmed against an absolute reference (NotChecked)"` into
`result.warnings` before serialising the sidecar. This states honestly what the differential
established (mutual agreement) and what it did not (absolute correctness), with **no
`GridSearchResult` schema change** (AT-3007/AT-3008 read the sidecar as `GridSearchResult`).
(If variants had disagreed with no oracle, the run would have errored `VariantsDiverge` with
zero artifacts — there would be no sidecar to warn in.)

**Determinism.** Real timings vary run-to-run; **no golden asserts a timing or a specific
winning assignment**. The sidecar records the measured numbers as-measured. The only
invariant tests may assert is winner-consistency (winner `.spv` ⟷ its own sidecar
assignment) and that a winner is selected.

### 1.6 Visibility change

**Two** promotions, both within `axc-driver` (zero logic change):

1. `bench_variant::check_correctness`: private `fn` → `pub(crate)` (called from `optimize.rs`).
2. `bench_variant::correctness_match`: private `fn` → `pub(crate)` (the differential's
   element comparator, §1.5.1; `ulp_tolerance_for_device` is already `pub(crate)`,
   `within_ulp_f32` stays FROZEN/untouched). `differential_mismatch` is a small NEW
   `pub(crate)` helper in `bench_variant.rs`:

   ```rust
   pub(crate) fn differential_mismatch(
       reference: &[Vec<u8>], got: &[Vec<u8>], ulp_tol: u32,
   ) -> Option<(usize, u32)> {
       // MODERATE fix (r3): BITWISE blob-equality fast-path FIRST. Bit-equal ⇒ match,
       // done — this makes a u32/copy kernel exact, and (critically) means two distinct
       // garbage NaN-pattern buffers, whose bytes differ, can NEVER NaN-collapse into a
       // spurious "match" via the f32 compare. Only bit-INequal buffers fall through to
       // the f32-ULP leg, which then absorbs legitimate reduction-order float jitter.
       if reference == got { return None; }                 // fast-path: bit-identical ⇒ match
       // bit-inequal ⇒ per-element f32-ULP compare (legit rounding vs gross divergence)
       correctness_match_blobs_as_f32(reference, got, ulp_tol)   // loops correctness_match
   }
   ```

   (The `reference == got` slice compare is exact `Vec<u8>` equality — the ~5-LOC fast-path
   the pessimistic MODERATE asked for. The f32 leg is unchanged from r2.)

**No `cross_validate_winner_module_wide` promotion (r3 MINOR fix).** AT-3015 is an **in-crate
`#[cfg(test)]` test living in `optimize.rs` itself** (§3) — a child test module sees its parent
module's **private** items via `use super::*`, so `cross_validate_winner_module_wide` stays
**private** and is still directly callable from the test. The r2 `pub(crate)` widening was
unnecessary and is dropped (no visibility churn beyond the two `bench_variant` comparator
promotions).

`seeded_inputs` / `derive_workgroups` are already `pub`; `pick_cpu_reference` /
`CorrectnessStatus` are already `pub(crate)` / `pub`. No other visibility churn.

## 2. Part B — the polish bundle

Selection rule: fix + AT ≤ ~50–100 LOC each, safe direction, observable behaviour. Rows that
exceed that, touch FROZEN code, or fix only unreachable-today paths are **explicitly deferred**
below.

### 2.1 IN — M3.22 PW-1 (referenced_holes false positive) — ~20 LOC + AT-3009

**Bug:** `validate_hole_refs` (`axc-hir/src/lower.rs:1316`) scans only *annotations* for
referenced holes (`collect_hole_refs_in_args`). A hole used **only** in a `shared[T,?WG]`
length is never marked referenced ⇒ spuriously reported `UnusedStrategyHole`. (The
M3.22 body-scan at `lower.rs:293` checks *undefined* len-holes but runs after
`validate_hole_refs` and does not feed `referenced_holes`.)

**Fix:** before the unused-hole check, collect `SharedDecl` len-hole names from the *parsed*
kernel body (`kd.body.node`, available at the `validate_hole_refs` call site,
`lower.rs:217`) via a small helper `collect_shared_len_hole_refs(body, &mut set)` and pass
them into `validate_hole_refs` (new `body_hole_refs: &HashSet<String>` param) so they seed
`referenced_holes`. A hole used only in a shared length is now referenced; a genuinely
unused hole still warns.

### 2.2 IN — M3.19a (out-of-i64-range annotation literal silently clamps) — ~30 LOC + AT-3010

**Bug:** five sites in `axc-parser/src/parser.rs` (549, 818, 832, 913, 926) do
`i64::try_from(value).unwrap_or(i64::MAX|MIN)` — an out-of-range integer literal in an
annotation arg is silently clamped. For a verification-oriented compiler this is a
fail-open.

**Fix:** add `ParseError::IntLiteralOutOfRange { span }` and a shared helper. The lexer stores
the literal **magnitude** as a non-negative `i128` (`TokenKind::IntLiteral { value: i128, .. }`,
`token.rs:141`), and the unary `-` is a SEPARATE `Minus` token, so the helper takes the
magnitude + the neg flag:

```rust
fn int_literal_checked(&mut self, value: i128, neg: bool, span: Span) -> Option<i64> {
    // ASYMMETRIC boundary: |i64::MIN| = 2^63 = 9223372036854775808 > i64::MAX = 2^63 - 1.
    let ok = if neg {
        value <= 9_223_372_036_854_775_808_i128            // accept -2^63 == i64::MIN
    } else {
        value <= i64::MAX as i128                          // accept +(2^63 - 1) == i64::MAX
    };
    if !ok {
        self.push_error(ParseError::IntLiteralOutOfRange { span });   // fail-closed
        return None;
    }
    Some(if neg { (-value) as i64 } else { value as i64 })  // in-range ⇒ exact
}
```

Replace all **five** `unwrap_or` sites (parser.rs 549/818/832/913/926) with this helper —
crucially the two NEGATED sites (818, 913, currently
`i64::try_from(value.wrapping_neg()).unwrap_or(i64::MIN)`) must accept `-9223372036854775808`
(i64::MIN) via the `neg` branch, not reject it. In-range literals parse unchanged; the
boundary values `i64::MAX` **and** `i64::MIN` are both still accepted.

**Do NOT touch the general body-literal path.** The five sites are annotation-arg /
optimization-log-record / strategy-candidate literals. The general typed *body* literal path
(parser.rs:1219, `IntLiteral { value, suffix: None, .. }`) is SEPARATE and MUST stay
untouched — `examples/scalar_demo.axc:38` legitimately holds
`let lua: u64 = 18446744073709551615u64;` (u64::MAX > i64::MAX) as a body expression, and
`typecheck.rs:4859` has `-9223372036854775808i64`; both must keep parsing. QA verifies the
diff touches only the five enumerated sites and that a u64-typed body literal > i64::MAX still
parses.

### 2.3 IN — M3.19b (log-opt writes LF separator into CRLF files) — ~20 LOC + AT-3011

**Bug:** `log_opt::splice_optimization_log_entry` (`axc-driver/src/log_opt.rs:297`, the
create-a-new-block path) pushes a bare `'\n'` regardless of the source's line ending,
producing mixed LF/CRLF in a CRLF file.

**Fix:** a pure helper `fn dominant_line_ending(source: &str) -> &'static str` (`"\r\n"` iff
the source contains `\r\n` and no lone `\n`; else `"\n"`) used at the create-path newline.
LF sources are byte-identical to today (helper returns `"\n"`).

**Scope (verified — resolves the pessimistic MODERATE).** The fix touches **only** the single
boundary newline at `log_opt.rs:297`. The spliced block body comes from
`format_optimization_log_block` (`log_opt.rs:162-171`), which — **verified by reading it** —
joins all items with `", "` and wraps them in a single `@optimization_log { ... }` string:
it emits **NO internal `\n`** (the block is one physical line). Therefore the boundary newline
is the ONLY newline the create-path introduces, and there is no intra-block mixed-ending
hazard. **AT-3011 is scoped to that boundary newline** — it asserts the create-path inserts a
`\r\n`-terminated block on a CRLF source (and stays byte-identical on an LF source); it does
**not** over-assert "no lone `\n` anywhere in the block interior" (moot — the interior has
none). `dominant_line_ending` is not applied to the block interior because the interior
contains no line separators to normalise.

### 2.4 IN — M3.19c (no per-note length cap on MCP append_optimization_log) — ~20 LOC + AT-3012

**Bug:** `append_optimization_log`'s `note: Option<String>` is unbounded; an agent can splice
an arbitrarily long note into the source.

**Fix:** `const MAX_NOTE_LEN: usize = 512;` checked in the MCP handler
(`mcp/tools/append_optimization_log.rs:handle`, alongside the existing `unit`/`verdict`
validation). **The cap is measured in BYTES** — `note.len()` (Rust `String::len()` is bytes) —
and the semantics are documented as such so implementation and spec agree (this resolves the
pessimistic MINOR: rather than switch to `chars().count()`, we *state* the unit is bytes and
use `len()`, which is the cheaper and unambiguous byte-budget the untrusted-agent surface
actually wants to bound). A note with `note.len() > MAX_NOTE_LEN` ⇒
`McpToolError::InvalidParams("note exceeds MAX_NOTE_LEN (512 bytes): <n> bytes")`. A note of
exactly 512 bytes is accepted (at-cap). (Enforced at the MCP boundary — the CLI `axc log-opt`
writer is unchanged; the cap protects the untrusted-agent surface, matching where the wart was
reported.) Existing `mcp_roundtrip.rs` append tests use short notes ("leader" etc., well under
512 bytes) → unaffected; QA confirms.

## 4. Correctness oracle

**Two faces with DISTINCT roles (r3), both device-keyed via `ulp_tolerance_for_device`
(frozen 4-ULP real HW / 8 llvmpipe) atop the FROZEN `within_ulp_f32` — no new tolerance math:**

1. **Variant-vs-variant differential — the DETECTOR (ALWAYS, when `policy != None`) — §1.5.1.**
   First passing variant seeds the reference; every later variant is compared within `ulp_tol`
   (bitwise fast-path then f32-ULP). A mismatch is **recorded** (the `divergence` ordinal set),
   **not** attributed. It can only tell you the variants *disagree*, never *which* is right (the
   reference is the first readback, not ground truth). Its output feeds the run-level decision.
2. **Registered CPU oracle — the ATTRIBUTOR (when `pick_cpu_reference` returns `Some`).**
   `pick_cpu_reference` (kernel-name + binding-shape keyed; `saxpy`/`vector_add`/
   `q4_0_dequant_matvec`, else `None`) → `check_correctness` tri-state. A real verdict sets
   `oracle_attributed`: `Failed` ⇒ `CorrectnessRejected` (the wrong variant, identified against
   ground truth); `Ok` ⇒ passes; `NotChecked` ⇒ no absolute ground truth this variant.

**Run-level decision (in `run_optimize`, after `grid_search`, before any write):**
- `divergence` empty ⇒ variants agreed ⇒ proceed (fastest wins). `NotChecked` ⇒ honest warning.
- `divergence` non-empty **and** `oracle_attributed` ⇒ oracle already rejected the wrong
  variant(s) ⇒ proceed with the survivors.
- `divergence` non-empty **and** NOT `oracle_attributed` ⇒ **`Err(OptimizeError::VariantsDiverge)`,
  ZERO artifacts** — divergence detected, attribution impossible, refuse to crown anyone
  (direction-independent; the r2 reference-attribution blind spot is closed).

No new oracle, no tolerance change, `within_ulp_f32` FROZEN. The only new code is
`differential_mismatch` (bitwise fast-path + a `correctness_match` loop, §1.6), the `RefCell`
reference plumbing, the ordinal/divergence/attribution cells, and the `VariantsDiverge` gate.

## 5. Edge cases

- **Coopmat kernel on Lavapipe:** every variant fails at the UNCHECKED `prepare_kernel`
  boundary — a `ShaderModuleCreationFailed`/`PipelineCreationFailed`-class `DispatchError`
  from the driver (NOT the preflight `CoopMatUnsupported`/`DeviceFeatureUnsupported` variants,
  which only `prepare_kernel_checked` emits — §1.3, corrected per the optimistic review) ⇒ all
  `BenchOutcome::Failed`, R3 fallback → ordinal 0, `fallback_used = true`; sidecar records the
  real per-variant `DispatchError` string. Artifacts still written (winner = ordinal 0) —
  consistent with existing fallback semantics. Whatever the exact `DispatchError` variant, it
  becomes `BenchOutcome::Failed` identically (grid_search's `bench_fn` returns
  `Result<SampleStats, String>`), so the R3 fallback path is unchanged; ATs must NOT assert a
  specific preflight variant name here.
- **Device-lost mid-search (disclosed, per pessimistic vendor_concern):** `derive_workgroups`
  + default `input_sizes` may over-cover a kernel's problem size; on a driver WITHOUT
  `robustBufferAccess` an OOB write can raise `VK_ERROR_DEVICE_LOST`, which is UNRECOVERABLE
  on the shared `VulkanContext` — one bad variant then poisons every subsequent
  `prepare_kernel`/dispatch ⇒ all `BenchOutcome::Failed` ⇒ R3 crowns ordinal 0 and STILL
  writes the winner `.spv` (`fallback_used = true`) for a winner that was never successfully
  measured. **Disclosed limitation:** M3.23 relies on `robustBufferAccess` (present on
  Lavapipe and all target HW) for OOB safety; a device-lost cascade yields an unmeasured
  fallback winner, surfaced honestly via `fallback_used = true` in the sidecar. No
  per-variant device recreation is attempted (out of scope).
- **Hole that parameterises `@workgroup` dims:** the harness derives geometry from the
  bench-target's declared workgroup (invariant capture), so all variants share one grid.
  Correct where the buffer is fully covered; under-coverage is caught by the oracle where
  registered, else `NotChecked`. Documented limitation; the M3.22 fixture (WG in a shared
  length, `@workgroup` fixed) is unaffected.
- **`policy == None`:** no oracle dispatch — one dispatch per variant (bench only); the
  differential is not evaluated (readback is opted out), so `VariantsDiverge` cannot fire.
- **Unattributable divergence (`policy != None`, no registered oracle):** variants disagree on
  `SEED=0` output ⇒ `divergence` non-empty, `oracle_attributed == false` ⇒
  `Err(OptimizeError::VariantsDiverge { ordinals, kernel })`, ZERO artifacts. Fires
  identically no matter which ordinal is the garbage one (§1.5.1). This is a *hard fail*, not a
  warning — correctness is undecidable, so no winner ships.
- **NaN-pattern collapse (r3 MODERATE):** two distinct garbage buffers whose bytes differ but
  whose f32 reinterpretation is all-NaN cannot false-"match" — `differential_mismatch`'s
  **bitwise fast-path runs first** (bit-inequal ⇒ fall through to the ULP leg, which flags them
  divergent), so they are correctly recorded as divergence.
- **F4 winner cross-validation** (module-wide) runs unchanged, before any write.
- **50 GB cap:** default `input_sizes` are 4 KB/buffer; no large allocation. No risk.

## 7. Anti-pattern / hard-rule compliance

- **#9 no mocking GPU:** the mock is *removed*; correctness runs on a real GPU (Lavapipe
  fallback in CI, `#[ignore]`-gated per M1.5+ convention). Headless = fail-closed, not fake.
- **Explicit types / explicit returns / no `>>`:** honored in all new code.
- **Fail-closed:** `GpuUnavailable` before any write; `VariantsDiverge` before any write;
  `IntLiteralOutOfRange` rejects; note cap rejects.
- **FROZEN code untouched:** `within_ulp_f32` and the 1e-3 tolerance are not modified; the
  differential (§1.5.1) reuses `correctness_match`/`within_ulp_f32` verbatim behind a bitwise
  fast-path.
- **No unattributed winner (r3):** the variant-vs-variant differential DETECTS divergence; with
  no CPU oracle to attribute it, `run_optimize` refuses to crown anyone (`VariantsDiverge`,
  zero artifacts) rather than trust the first-seen (possibly-garbage) variant as the reference.
  The fast-but-racy variant can never win, and — the r2 blind spot — neither can it win *by
  seeding the reference*.
- **Codegen byte-identical:** no emitter change ⇒ corpus goldens unaffected.
