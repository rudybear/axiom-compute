## 1. Problem & honest current state (verified in-tree)

DESIGN.md §3.2 promises: `@precondition(expr)` / `@postcondition(expr)` → *"Runtime-checkable contract → Debug-mode assertion"*, enabled by `axc compile --debug`. ROADMAP FG.4: *"Currently parsed and HIR-validated, but never lowered."* The verified reality is narrower and must be stated plainly:

1. **`@precondition` accepts ONLY `AnnotationArg::Bool(true)`** (`axc-hir/src/lower.rs:111-125`; anything else → `HirError::UnsupportedPrecondition`, `validate.rs:72`). A real predicate is not just un-lowered — it is **not representable** today.
2. **`@postcondition` is not handled at all** — it falls through to `HirError::UnknownAnnotationInM0` (`validate.rs:60`).
3. **The annotation-argument grammar has NO relational/arithmetic operators.** `parse_annotation_arg` (`axc-parser/src/parser.rs:583-659`) yields only `Int / Bool / String / Ident / Call{name,args} / Hole / HoleRef`. So `@precondition(n > 0)` **cannot be parsed**. The one structured composite that already parses is **`Call{name, args}`** (used today by `@complexity(O(n))`).
4. **No `--debug` flag exists.** `CodegenOptions` (`axc-codegen/src/emit.rs:49-57`) has only `spirv_version` + `generator_magic`.
5. **No atomic op exists in codegen.** (grep: zero `OpAtomic*`.)
6. **Metadata is schema v3**, `SUPPORTED_SCHEMA_VERSIONS=[1,2,3]`, `CURRENT=3` (`axc-runtime/src/metadata.rs:100-135`). The runtime binds descriptors generically from `binding_plan.buffers` keyed by `buffer_position` (`context.rs:1628-1636`, `834-871`).
7. **at_1115** (`mcp_roundtrip.rs:543-575`): `check_saxpy` (`bench_variant.rs:411-448`) compares `y_out[i]` vs `y_in[i]` (α=0 ⇒ expected == y_in) at a **fixed 4-ULP** tolerance (`within_ulp_f32`, `bench_variant.rs:498-508`). On Lavapipe/Mesa 25.2.8, 9/1024 elements exceed 4 ULP — a pre-existing software-rasterizer FP-lowering drift. Max observed ULP is **not currently reported** (the reason string carries only the count).

**Design consequence:** the honest, tightly-scoped v1 expresses predicates through the **existing `Call` grammar** (a whitelisted predicate DSL) — **zero parser/lexer change** — and reserves infix-operator sugar (`n > 0`) for a follow-up (avoids anti-pattern #6's `>>` class of problems and a parser rewrite). This keeps annotations first-class structured data (anti-pattern #5), not strings.

## 2. What a runtime assert MEANS on a GPU (mechanism)

There is no portable trap/abort. The design is a **host-observed debug-flag SSBO**, injected **only** under `--debug`:

- **Injected binding.** One SSBO at descriptor set 0, `Binding = num_user_buffers` (one past the last user binding). Type `buffer[u32]`, length **2 words**: `flag[0]` = precondition violation bitmask, `flag[1]` = postcondition violation bitmask. It is **injected, never a reused user buffer** (a user buffer must never be corrupted). Present in the SPIR-V, the descriptor layout, and the metadata **only** when `--debug` is on.
- **Write semantics — race-safe + informative.** A failing condition of index `i` (`i∈[0,32)`) executes `atomicOr(flag[word], 1u << i)` (`OpAtomicOr`, semantics **Relaxed/0**). `atomicOr` is (a) **atomic**, and (b) **idempotent** (set-a-bit), so any number of failing invocations converge to the same bitmask regardless of order. The atomic executes **only on the failing branch** — the happy path issues zero atomics.
- **CRITICAL-1 fix — atomic scope keyed on the emitted memory model.** `emit.rs:152-162` emits `MemoryModel::Vulkan` + `Capability::VulkanMemoryModel` **whenever the kernel uses coopmat**, else `MemoryModel::GLSL450`. Under the Vulkan memory model, an `OpAtomicOr` with **`Scope::Device`** REQUIRES the `VulkanMemoryModelDeviceScope` capability (spirv-val-enforced) — which would break the "no new `OpCapability`" claim. **Rule (v1):** the scope constant is chosen by the memory model actually emitted for the kernel:
  - **`Scope::QueueFamily`** under `MemoryModel::Vulkan` (coopmat kernels). QueueFamily gives whole-dispatch atomicity and needs **no capability** beyond `Shader` + the already-present `VulkanMemoryModel`.
  - **`Scope::Device`** under `MemoryModel::GLSL450` (non-coopmat kernels). Device-scope Relaxed `OpAtomicOr` on a 32-bit StorageBuffer `u32` is valid with `Capability::Shader` alone.
  Both scope constants are emitted conditionally from the same predicate that already drives the memory-model branch (`uses_coopmat`). Net capability set for **either** path is **identical to the baseline** (Shader; +VulkanMemoryModel iff coopmat) — the atomic adds nothing. Preconditions ARE lowered on coopmat kernels (e.g. `@precondition(gt(K,0))` on a q4km coopmat matmul), so the coopmat/QueueFamily leg is exercised, not hypothetical.
- **Observational-only semantics (design rule — sidesteps `BarrierInDivergentContext`).** A violated condition **does NOT short-circuit**: the injected check is a self-contained `OpBranchConditional %bad → OpAtomicOr → OpBranch merge` (`OpSelectionMerge`, structured CF), after which the kernel body runs **unchanged** with the offending inputs. There is **NO early return / abort**. Consequence to document: on a violated precondition the body still executes (and may itself fault/OOB on genuinely bad inputs) — acceptable for a debug tool, but it is the contract. Because there is no divergent return before any workgroup barrier, the barrier-in-divergent-CF bug class is not touched. Postcondition insertion assumes a **single trailing `OpReturn`** (the current codegen shape; mid-loop early return is deferred per body.rs/AT-323) — a kernel with multiple returns guards only the trailing one; state this assumption, do not silently mis-handle.
- **Host surfacing.** The runtime zero-inits `flag`, dispatches, waits the fence, and reads `flag` back **through the existing NonCoherent staging path** — `vkInvalidateMappedMemoryRanges` on non-`HOST_COHERENT` memory (`buffers.rs` `Coherency::NonCoherent`; honoring `context.rs` `force_noncoherent_staging` / `AXC_FORCE_NONCOHERENT_STAGING`). This is the SAME readback path user output buffers use, so the debug tool **fails CLOSED** (a real violation is always observed) on non-coherent devices; skipping the invalidate would make it fail-OPEN (silently miss violations) — forbidden. If nonzero it decodes each set bit against the metadata `conditions[]` and returns a **typed error** — `DispatchError::DebugCheckViolation { preconditions: Vec<String>, postconditions: Vec<String> }` — naming exactly which conditions failed. `flag == {0,0}` ⇒ dispatch returns `Ok` with output identical to the release run.

**Why not a `gid==0` single-writer guard:** uniform preconditions produce the same predicate on every invocation, and `atomicOr` is idempotent, so an all-invocations write is correct and avoids a divergent-branch/single-lane special case. The atomic (not a plain store) makes it data-race-free under the Vulkan memory model too.

## 3. v1 predicate DSL (Call-form, ZERO parser change)

| Predicate | Arity | Operands (v1) | Kind |
|---|---|---|---|
| `gt ge lt le eq ne` | binary | each operand = integer literal **or** Ident naming a **scalar push-constant param** (`u32`/`i32`/`f32`) | pre + post |
| `is_finite` | unary | `elem(buf)` only | **post only** |
| `elem(buf)` | operand | `buf` = a `buffer[f32]`/`buffer[i32]`/`buffer[u32]` param the kernel wrote | **post only** |

- **Conjunction** = multiple `@precondition` / `@postcondition` annotations on the kernel (each gets its own bit). No `and/or/not` combinator in v1.
- **`@precondition(true)`** stays valid (back-compat) and lowers to **nothing** (no bit, no check).
- **Signedness/type**: comparison op chosen from the referenced scalar's `ScalarTy` — `u32`→`OpUGreaterThan…`, `i32`→`OpSGreaterThan…`, `f32`→`OpFOrdGreaterThan…`. A bare integer literal takes the other operand's type.

**Rejected at HIR (non-silent, hard errors):**
- Buffer operand in a **precondition** → `HirError::PreconditionOperandNotScalar` (preconditions are thread-uniform-only in v1).
- Non-whitelisted call (e.g. `foo(x)`, `mod(...)`, `and(...)`) → `HirError::UnsupportedDebugPredicate { name }`.
- `> 32` conditions of one kind → `HirError::TooManyDebugConditions { kind, got }`.

**Deferred (documented, §7):** infix operator sugar; `and/or/not`; `mod`/`divides`; buffer operands in preconditions; f64; multi-output / non-`gid(0)` postconditions.

## 4. Lowering rules table (source form → lowered code, **only under `--debug`**)

The **`%bad` (violation) form is pinned exactly** so NaN fails LOUD (an ordered `FOrd*` compare returns *false* for a NaN operand ⇒ `OpLogicalNot` ⇒ `%bad = true` ⇒ violation FLAGGED). The Coder MUST use the `FOrd`-family compare + `OpLogicalNot` of the RESULT — NOT `FUnord*`, and NOT inverting the comparison operator (either would let NaN slip through silently). `<scope>` = `QueueFamily` (Vulkan mem model / coopmat) or `Device` (GLSL450), per §2 CRITICAL-1.

| Source | Insertion point | HIR node | SPIR-V (behind `debug_checks`) |
|---|---|---|---|
| `@precondition(true)` | — | trivial (bit=None) | *(nothing — back-compat preserved)* |
| `@precondition(gt(s, k))`, `s` scalar param, `k` int lit | function **entry** (before body) | `DebugCheck{Pre, Gt, ScalarRef(s), Lit(k), bit=i}` | load `s`; `%c = OpU/S/FOrd GreaterThan`; **`%bad = OpLogicalNot %c`**; `OpSelectionMerge`; `OpBranchConditional %bad → OpAtomicOr(flag[0], <scope>, Relaxed, 1<<i) → OpBranch merge` |
| `ge/lt/le/eq/ne(...)` | entry | analogous | analogous **ordered** (`FOrd*`) / `U`/`S` compares, `%bad = OpLogicalNot` of the RESULT |
| `@postcondition(<cmp over scalars>)` | function **exit** (before the single trailing `OpReturn`) | `DebugCheck{Post, …, flag word 1}` | as above, `flag[1]`, own `OpSelectionMerge` |
| `@postcondition(ge(elem(buf), k))`, lowerable (§5) | exit | `DebugCheck{Post, Ge, BufElem(buf@gid0), Lit(k)}` | load `buf[gid(0)]`; compare; `%bad=OpLogicalNot`; on-fail `OpAtomicOr(flag[1], <scope>, Relaxed, 1<<i)` |
| `@postcondition(is_finite(elem(buf)))`, lowerable | exit | `DebugCheck{Post, IsFinite, BufElem(buf@gid0)}` | `%n=OpIsNan; %f=OpIsInf; %bad=OpLogicalOr %n %f; OpSelectionMerge; OpBranchConditional %bad → atomicOr(flag[1],…) → merge` |
| `@postcondition(...)` NOT lowerable (§5) | — | dropped | *(nothing)* + `HirWarning::PostconditionNotLowerable` |

Atomic constants (the `<scope>` id — `QueueFamily` or `Device` per the memory model — `Relaxed`=0 semantics id, `1<<i` masks) are emitted once and reused. **No `OpCapability` beyond the baseline set** (`Shader`; `+VulkanMemoryModel` iff the kernel already uses coopmat).

## 5. Postcondition lowerability gate (honest v1 scope)

Preconditions are uniform (push-constant) ⇒ cheap ⇒ **fully lowered**. Postconditions over an **output buffer** are the risky/expensive case, scoped as *"per-thread check of the value this thread itself wrote — not a global property."*

`elem(buf)` is **lowerable iff ALL hold**:
1. kernel is **non-coopmat** (`coop_matrix.is_none()`), and
2. kernel declares **no `shared[T,N]`** (`shared_memory_bytes == 0`), and
3. **CRITICAL-2 — the write must UNCONDITIONALLY DOMINATE kernel exit.** The kernel body contains a **top-level** `HirStmt::BufferWrite { buffer_binding == buf, index == gid(0) }` (the actual HIR node — r1 wrote `IndexAssign` loosely) that is **NOT nested inside any `HirStmt::If` / `HirStmt::ForRange` / `HirStmt::While`**. This is a **conservative SYNTACTIC dominance check — NO dataflow analysis in v1**: "unconditional" ≡ "appears directly in the kernel's top-level statement list, not inside a conditional/loop branch." It reuses the exact discipline already proven in `body.rs:836` (`stmt_reassigns_binding_unconditionally`: "an assign inside a conditional branch does NOT dominate the back-edge" — same non-descend rule).

**Why condition 3 must require dominance, not mere existence (the soundness hole r1 missed):** the current codegen FULLY supports guarded writes — `if (i < n) { buf[i] = … }` (`body.rs:579` `HirStmt::If`, `body.rs:850` CONDITIONAL reassignment, `OpSelectionMerge`). Dispatches are padded to `ceil(n/wg)*wg > n`, so for threads where the guard is false the write never happens. An **unconditional** exit-time read of `buf[gid(0)]` on those threads is then either OOB (buffer sized exactly `n` ⇒ device fault) or reads UNWRITTEN memory ⇒ a **spurious** `is_finite`/compare violation the kernel itself avoided. r1's "in-bounds by the write's own safety" is TRUE only when the write is unconditional — hence the dominance requirement.

When lowerable, the postcondition **reads the same index `buf[gid(0)]` the kernel unconditionally wrote**, so it is **in-bounds by the write's own safety** (no separate bounds guard, no OOB UB). This covers the elementwise 1-output-per-thread class (saxpy / vector_add / q4km-matvec). Otherwise — including a guarded/loop-nested `buf[gid(0)]` write — → **`HirWarning::PostconditionNotLowerable { buf, reason }`** (surfaced, not silent), compilation **succeeds**, and NO unguarded exit read is emitted. This is the documented honest limitation, not a silent drop. (v1 does NOT lower the check under the write's own predicate — that is a documented follow-up in §9; conservative-reject is the sound v1 choice.)

## 6. Zero-cost-when-off (the golden-identity gate — explicit)

- `CodegenOptions` gains `debug_checks: bool`, **default `false`**. `Default` and every existing call site are unchanged in behavior.
- With `debug_checks == false`: **no injected binding, no atomic, no new capability, no new type, no metadata `debug_checks` field.** The emitted SPIR-V is **byte-identical to today**.
- **Gates (blocking):**
  - **AT-2838** (empty-kernel full-byte golden `.spv`) stays green.
  - **AT-2866 (new):** a `@precondition(gt(n,0))`-bearing kernel compiled `--debug` OFF is **byte-identical** to (a) a committed golden and (b) the same source with the annotation removed. This proves the annotation is inert without `--debug`.
- Release metadata is unchanged from today (the `debug_checks` field is **omitted** when off, so any metadata-comparison test is unperturbed).

## 7. Interface / metadata changes

- **Schema v4.** `KernelMetadata` gains `#[serde(default, skip_serializing_if = "Option::is_none")] pub debug_checks: Option<DebugChecksMeta>`. `SUPPORTED_SCHEMA_VERSIONS = [1,2,3,4]`, `CURRENT_SCHEMA_VERSION = 4`. v1/v2/v3 sidecars still load (`debug_checks` defaults `None`). The `skip_serializing_if` (r2) is REQUIRED so release metadata emits **no `debug_checks` key at all** (not `"debug_checks": null`), keeping §6's "release metadata unchanged from today" literally true and any metadata-comparison test unperturbed.
- `DebugChecksMeta { flag_binding: u32, flag_len_words: u32 /* =2 */, conditions: Vec<DebugConditionMeta> }`.
- `DebugConditionMeta { kind: DebugCheckKind /* Pre|Post */, bit: u32, text: String, line: u32 }` — `text` is the human predicate rendering used to name a violation in the host error; `bit` decodes the flag word.
- Present in metadata **only** under `--debug`.
- **Descriptor plumbing (explicit — closes the pessimistic integration gap).** Under `--debug` the injected flag binding is **APPENDED to `binding_plan.buffers`** at position `num_user_buffers`, so all FOUR derivations that read that list agree uniformly: (a) the SPIR-V decoration `DescriptorSet=0, Binding=num_user_buffers`, (b) the descriptor-set-layout build (`build_compute_pipeline`), (c) the descriptor-pool sizing (`context.rs:1636` uses `binding_plan.buffers.len()`), and (d) the generic bind loop (`context.rs:1628`, keyed on `buffer_position`). This is the SOLE reason a debug artifact is `N+1` bindings (consistent with §7.1 rewrite-verify). The flag binding is NOT a detached metadata-only field — a detached field would leave the DSL/pool/bind loop unaware of a descriptor the SPIR-V references (VUID descriptor-not-in-layout ⇒ pipeline-create failure).
- **Runtime path (under debug metadata):** allocate the 2-word flag buffer, zero-init, bind at `flag_binding` (== `num_user_buffers`), dispatch, wait fence, **read back via the NonCoherent invalidate path** (§2 host surfacing — `vkInvalidateMappedMemoryRanges`, honoring `force_noncoherent_staging`), decode `flag[0]`/`flag[1]` against `conditions[]`, and return `DispatchError::DebugCheckViolation{…}` on nonzero (fail-CLOSED).

### 7.1 Interaction with M3.16 rewrite-verify's interface gate (stated rule)

A `--debug` kernel has an **extra binding** ⇒ it is a **different artifact class**. **Rule: rewrite-verify operates on RELEASE (`--debug` OFF) artifacts only.** Its interface gate compares binding counts; a debug artifact (N+1 bindings) vs a release artifact (N) — or any debug-involving pair — **fails closed / REJECTs**, which is correct. Debug-to-debug comparison is explicitly out of scope. **AT-2869** asserts a debug kernel's metadata carries the extra binding (documenting that rewrite-verify would reject it) — the rule is enforced by the existing gate, not by new code.

## 10. at_1115 — Lavapipe-drift resolution (self-contained secondary item)

**Decision: Lavapipe-only ULP widening, keyed on device name. The NVIDIA / real-hardware path is NEVER weakened.**

- **Measurement step (required, do first).** Instrument `check_saxpy` (temporarily / via a logged max) to report the **max observed ULP** across the 1024 elements on Lavapipe/Mesa 25.2.8, not just the count. Record the number in the commit message + this spec. (Expectation: small — a few tens of ULP from Mesa's `a*x+b` lowering of the α=0 case; the Coder fills in the measured value.)
- **Fix.** `check_saxpy` / `check_vector_add` take a **device-derived** tolerance via a helper `ulp_tolerance_for_device(device_name: &str) -> u32`. **Device match keys on the `"llvmpipe"` substring** (case-insensitive: `name.to_ascii_lowercase().contains("llvmpipe")`) — this is the actual `VkPhysicalDeviceProperties.deviceName` Lavapipe reports (`"llvmpipe (LLVM x.y.z, N bits)"`); the string `"lavapipe"` **NEVER appears** and MUST NOT be matched. Returns **4** for every device NOT matching `llvmpipe` (NVIDIA, AMD, Intel, real hw — frozen), and a **widened** value for the `llvmpipe` device = the next power of two above the measured max. The bench path already exposes `ctx.physical_device_name()` (`context.rs:1352`).
- **`within_ulp_f32` is NOT touched (frozen invariant).** It is `pub(crate)` and reused VERBATIM by M3.16 rewrite-verify's differential comparator at a fixed 4 ULP (`bench_variant.rs:496-498`); widening it would silently loosen M3.16. The per-call tolerance is threaded ONLY through `check_saxpy` / `check_vector_add` (a new `u32` argument), leaving `within_ulp_f32`'s signature and body unchanged.
- **Ceiling rule (r2 — no silent clamp).** The widened value is `next_pow2(measured_max)`. If `measured_max` would force a value **> 64**, the milestone **FAILS / re-measures** — it does NOT clamp to 64 (a clamp would leave at_1115 flaky while claiming a fix). The Coder MUST record the measured max in this spec + the commit message.
- **Justification.** The drift is a pre-existing software-rasterizer FP-lowering quirk (Mesa 25.2.8 bump), not a kernel-quality signal; α=0 saxpy should be exact and is only perturbed by the CPU-rasterizer's lowering. Widening is scoped to the driver that exhibits it; the meaningful (real-hardware) bar stays at 4 ULP.
- **Rejected: a global re-baseline** — it would loosen the real-hardware tolerance, which is forbidden ("NEVER weaken the NVIDIA path").
- **AT-2876** pins: `ulp_tolerance_for_device("NVIDIA…")==4`, `ulp_tolerance_for_device("llvmpipe (LLVM …)")==widened`, and a **guard leg** that a NON-`llvmpipe` device name stays at **4** (proving `within_ulp_f32`'s M3.16 reuse is unweakened); at_1115 passes deterministically on Lavapipe; NVIDIA correctness gate unchanged.
