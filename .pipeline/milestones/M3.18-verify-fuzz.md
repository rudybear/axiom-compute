## 1. Problem & honest current state (verified in-tree)

Parent AXIOM's CLAUDE.md advertises `axc verify` (annotation-completeness for `@strict` modules) and `axc test --fuzz` (auto-generate inputs from `@precondition` constraints). AXIOM-Compute inherited the *thesis* but never built either. Verified reality:

1. **`@strict` is a compiler NO-OP.** `lower.rs:167` — `"strict" => {}` with the comment *"validation of the strict discipline is done by the QA agent, not the compiler."* Nothing checks that `@intent` + `@complexity` + a pre/postcondition are actually present. The discipline is enforced only by human/agent review.
2. **The M3.17 predicate DSL is fully lowered and codegen-ready.** `axc compile --debug` lowers a whitelisted Call-form DSL (`gt/ge/lt/le/eq/ne/is_finite`) to `axc_hir::DebugCheck { kind, op, ty, lhs, rhs, bit, text, span }` (`hir.rs:152`), and the runtime decodes the injected flag SSBO via the dedicated debug entry point **`VulkanContext::dispatch_debug_checked` (`dispatch.rs:144`)** → `DebugDispatchOutcome { outputs, flag_words: [u32;2], conditions }` → `.into_result()` (`dispatch.rs:210`) → `decode_debug_flags` → `DispatchError::DebugCheckViolation { preconditions, postconditions }`. **CRITICAL CORRECTION (r2/C-1):** the plain `context.rs:1736::dispatch_handle` is the *raw* dispatch (validate → submit → `Ok(outputs)`) and performs **NO flag decode** — it is debug-unaware. The fuzz oracle MUST use `dispatch_debug_checked`, not `dispatch_handle`; the former internally *calls* `dispatch_handle` after pushing a freshly-zeroed `[0u8;8]` flag SSBO (`dispatch.rs:170-177`) and pops the flag readback into `flag_words` (`[precondition_bits, postcondition_bits]`). `flag_words` is `pub`, so the fuzzer may either call `.into_result()` for the typed error OR inspect `flag_words` directly for exact-bitmask assertions (the violate leg does the latter). Both the API and `flag_words` are already `pub` — **zero runtime change**. **This is the fuzz oracle's engine — it exists and is GPU-proven (AT-2870..2873).**
3. **The M3.17 `DebugCheck` operands are exactly `ScalarRef{name, position} | Lit(i64)` with a resolved `ty ∈ {U32, I32, F32}`** (`hir.rs:143`). For preconditions, both operands are always scalar/lit (buffer operands are hard-rejected: `PreconditionOperandNotScalar`). **This is precisely the shape interval arithmetic can solve — the satisfier consumes these structs directly, no re-parse.**
4. **Known M3.17 LOW (ROADMAP backlog, 2026-07-14):** `@precondition`/`@postcondition` with **arity ≠ 1** (e.g. a comma-conjunction `@precondition(gt(n,0), gt(alpha,0))`) is **SILENTLY DROPPED** — `lower.rs:118` / `lower.rs:142` guard `if ann.node.args.len() == 1` with **no `else`**. A verification tool that fails open is worse than none. M3.18 turns this into a **verify-surfaced diagnostic** WITHOUT changing compile behavior (see §4.C2, decision & justification).
5. **CLI surface** (`cli.rs`): `Compile{--debug}`, `Lex`, `Optimize`, `Mcp`, `Bench`, `RewriteVerify`. The M3.16 `RewriteVerify` handler (`main.rs:94`) is the exact sibling pattern for a "compile-front-end → JSON verdict on stdout → mapped exit code" CLI primitive; `rewrite_verify.rs` is the sibling for seeded fills, `TolerancePolicy`, `find_nondeterminism`, and verdict-JSON style.

**Design consequence:** both commands are pure *driver-layer orchestration* over existing, GPU-proven machinery. `verify` = front-end (lex/parse/HIR) + a handful of CPU checks. `fuzz` = interval-satisfier (new, pure, unit-testable) + the M3.17 debug-dispatch as the runtime oracle + the M3.16 determinism self-check. No new SPIR-V, no new capability, no codegen touch.

## 2. `axc verify` — static annotation/consistency checker (CPU-only, zero GPU)

### 2.1 Contract

```
axc verify <file.axc> [--json]
```

- Runs the compile **front-end only**: lex → parse → `lower_module` (HIR). **Never** calls codegen, never touches Vulkan. CI-friendly, deterministic, fast.
- Inspects BOTH the raw AST annotation list (`kd.annotations`, for `@strict` presence and the arity-≠1 drop that HIR normalizes away) AND the lowered HIR (`hir_errors`, `hir_warnings`, `KernelAnnotations`).
- Human summary to stdout by default; `--json` emits the machine-readable report (verdict first key). Exit code is the same in both modes.
- **Zero mutation of compile behavior** — verify is read-only over the front-end; it adds diagnostics the compiler does not (and must not) emit.

### 2.2 Checks (v1)

| # | Check | Severity | Source |
|---|---|---|---|
| **C1** | **`@strict` discipline completeness.** IF `@strict` is present on a kernel, require ALL of: `@intent` present, `@complexity` present, and **≥1 pre/postcondition** (a real Call-form predicate OR a `@precondition(true)` OR any `@postcondition`). Missing any ⇒ **error**, naming exactly which element is absent. (CLAUDE.md `@strict` rule verbatim: *"@intent + @complexity + at least one pre/postcondition"*.) | error | AST + HIR |
| **C2** | **Predicate DSL well-formedness.** (a) Surface every `HirError` from lowering the M3.17 DSL (`UnsupportedDebugPredicate`, `PreconditionOperandNotScalar`, `TooManyDebugConditions`, arity-≠2, ambiguous two-literal, `UnsupportedPrecondition`) as verify errors. (b) **NEW — the arity-≠1 silent-drop diagnostic:** for each RAW annotation named `precondition`/`postcondition` whose `args.len() != 1`, emit `verify` error `predicate_arity_dropped` (a comma-conjunction is not a v1 conjunction form; each predicate needs its own annotation). Detected from the AST; **compile behavior is unchanged** (the drop still happens in `lower.rs` — verify only *reports* it). | error | AST + HIR |
| **C3** | **`@workgroup` sanity.** product == 0 (already `HirError` — surfaced). product > **1024** ⇒ **portability warning** (`workgroup_over_portable_min`): 1024 is the Vulkan-guaranteed minimum `maxComputeWorkGroupInvocations`; a larger workgroup may fail on conformant devices. Non-fatal (device-specific; verify is CPU-only). | warning | HIR |
| **C4** | **Un-lowerable postconditions.** Surface every `HirWarning::PostconditionNotLowerable` as a verify warning (*"this `@postcondition` will NOT be checked at runtime"*) — valuable because a silently-inert contract is a false sense of safety. | warning | HIR |
| **C5** | **Front-end errors.** Any lex/parse/HIR error ⇒ verify **error** (a file that does not compile cannot be `@strict`-clean). | error | front-end |

**PASS iff zero errors.** Warnings never fail the command (CI stays green on portability advisories) but are always reported.

### 2.3 Decision & justification for C2(b) (the arity-drop)

The task mandates surfacing the M3.17 LOW *without changing compile behavior*. Two options were considered:

- **(rejected) Fix `lower.rs` to hard-error on arity≠1.** This changes compile behavior for existing sources and risks perturbing the golden gates (AT-2866). It also conflates "the compiler rejects" with "the verifier warns" — the compiler's fail-open is documented M0 lineage.
- **(chosen) Detect in `verify` from the AST.** verify re-walks `kd.annotations`, finds `precondition`/`postcondition` with `args.len()!=1`, and emits `predicate_arity_dropped`. `axc compile` still silently drops (unchanged). The verifier is the correct home: it is the tool whose entire job is to catch the fail-open. This keeps compile byte-identical (frozen invariant) while closing the fail-open at the verification layer — exactly the split the milestone asks for.

### 2.4 verify JSON schema (`--json`)

```json
{
  "verdict": "PASS",                 // PASS | FAIL | ERROR   (FIRST key)
  "milestone": "M3.18",
  "file": "examples/precondition_saxpy.axc",
  "kernel": "precondition_saxpy",    // null if no kernel parsed
  "checks": [
    { "check": "strict_discipline",   "status": "pass" },
    { "check": "predicate_dsl",       "status": "pass" },
    { "check": "workgroup_sanity",    "status": "pass" },
    { "check": "postcondition_lowerable", "status": "warn", "warnings": 1 }
  ],
  "diagnostics": [
    { "severity": "warning", "code": "postcondition_not_lowerable",
      "message": "@postcondition over buffer `y` is deferred; NOT checked at runtime",
      "line": 30 }
  ],
  "summary": { "errors": 0, "warnings": 1 }
}
```

- `verdict == "PASS"` iff `summary.errors == 0`. `"FAIL"` when errors > 0 (discipline/DSL/front-end). `"ERROR"` for usage/IO (unreadable file, no kernel at all is a FAIL not ERROR — the file parsed but is empty of kernels ⇒ nothing to verify ⇒ error-level `no_kernel`).
- `verdict` is the first serialized key (struct field declared first; serde preserves order — same technique as `VerifyReport`, AT-2842).

### 2.5 verify exit codes

`exit_code_for_verify(verdict)`: `PASS → 0`, `FAIL → 1`, `ERROR → 2`. Mirrors `exit_code_for_verdict` (rewrite_verify.rs:950).

## 3. `axc test --fuzz` — precondition-satisfying input fuzzer with a runtime oracle

### 3.1 Contract

```
axc test --fuzz <file.axc> [--runs N] [--seed S] [--debug-oracle] [--violate]
                           [--buffer-sizes a,b,..] [--size N] [--workgroups x,y,z]
                           [--scalar-window W] [--strategy-value name=value ...]
```

- `--fuzz` is currently the ONLY mode of `axc test`; absence ⇒ usage ERROR guiding the user to `--fuzz` (leaves `axc test --unit`/other modes as a clean future extension — matches ROADMAP phrasing `test --fuzz` exactly). `test` is a NEW subcommand.
- **v1 folds fuzz under `axc test`, not under a flag on an existing command** — the roadmap names it `test --fuzz`, and a fuzzer's surface (runs/seed/oracle knobs) is distinct enough from `compile`/`rewrite-verify` to warrant its own subcommand. MCP exposure is **DEFERRED** (§11) — justified: the fuzzer's value is CI/CLI-driven regression, and an MCP tool balloons the JSON-RPC contract for no proven agent-loop need in v1 (same call the M3.17 spec made for its `--debug` MCP option).
- Writes the fuzz `FuzzReport` JSON to stdout (always, both modes) + a human summary; exits with the verdict's mapped code.
- GPU absence ⇒ `SKIPPED`/`gpu_unavailable`, exit 0 (CI-friendly, first-class — mirrors rewrite-verify step 5).

### 3.2 The fuzz oracle triad (the honest core — this is ALL a no-reference fuzzer can check)

There is **no reference output** (that is what rewrite-verify has, and it is a different tool). A fuzzer with precondition-satisfying inputs can honestly check exactly three things:

- **(a) No device fault / timeout.** Each run's dispatch must return without a device-lost / fence-timeout error (honoring `AXC_FENCE_TIMEOUT_MS`). A fault on a *precondition-satisfying* input is a real signal (the kernel misbehaves on valid input). Reported as a `device_fault` counterexample. **(r2/W-2 honesty note: when `--debug-oracle` is ON, leg (a) runs on the DEBUG artifact — `compile_source_with_meta_debug(src, true)` + `dispatch_debug_checked` — which carries the extra flag SSBO + postcondition atomics and a different binding count than the release pipeline; a clean leg (a) then certifies the DEBUG artifact, not the release one. The report JSON records which artifact each leg exercised, per the M3.16 honesty convention.)**
- **(b) Postconditions hold at runtime — THE PAYOFF.** This is why the milestone pairs with M3.17. The kernel is compiled **with `--debug` (`compile_source_with_meta_debug(src, true)`)** so the injected debug-flag SSBO + postcondition atomics are present. After each dispatch the runtime decodes the flag words via **`dispatch_debug_checked` (`dispatch.rs:144`) → `DebugDispatchOutcome { outputs, flag_words:[u32;2], conditions }`**. The fuzzer inspects `flag_words` (or calls `.into_result()` → `DispatchError::DebugCheckViolation { preconditions, postconditions }`). **NOT `dispatch_handle` (r2/C-1) — that path never decodes and would false-PASS every run.**
  - `flag_words[1] != 0` (`postconditions` non-empty) ⇒ the kernel **violated its own contract on a valid input** ⇒ **FUZZ FAIL** with the offending scalars + condition text as the counterexample. **This is a found bug — the fuzzer's product.**
  - **The precondition discriminator (r2/C-2, made TOTAL + DEFER-EXEMPT in r3).** On EVERY run — not only when a bit fired — the fuzzer performs an **UNCONDITIONAL host re-check** (r3/fix-4 totality): it re-evaluates every source Pre predicate **in `f32`** (r3/C-1new) on the **std430-decoded bytes actually written into the push-constant buffer and dispatched** (the byte-identical value the GPU saw — never an `f64` re-derivation), and it observes `flag_words[0]`. This makes all four host×GPU quadrants defined, which is what lets the check catch the *inert-check* case (a check that should have fired but did not).
    - **DEFERRED-CONDITION EXEMPTION FIRST (r3/C-2new).** Two-`ScalarRef` relational preconditions (`gt(a,b)`) ARE lowered and CAN fire (`lower.rs:587`), but the v1 satisfier DEFERS them (§3.4) and samples their scalars in the default window — so such a bit firing is EXPECTED, a documented honest v1 limitation, NOT a bug in the tool or the compiler. Therefore, **before** the quadrant table, the fuzzer attributes each fired `flag_words[0]` bit to its condition (via `DebugCheck.bit`). If the fired bit belongs to a condition the satisfier **did not constrain** (a deferred relational, or any otherwise-unconstrained condition), the verdict is **`UNCONSTRAINED_PRECONDITION_FIRED`** — a **SKIPPED-class** outcome, **exit 0 with a loud warning `note`** listing the exempt condition(s) and the sampled scalars. **Justification for exit 0 (SKIPPED-class):** the deferral is a *documented, honest* v1 limitation already surfaced by the `relational_constraint_deferred` note (§3.4); the satisfier never claimed to satisfy the condition, so its firing is neither `satisfier_unsound` (the satisfier made no promise to break) nor miscompile-suspect (the check fired correctly on an unconstrained input) — failing the run would penalize a limitation the tool honestly disclaims. CI that wishes to gate can still key on the distinct `UNCONSTRAINED_PRECONDITION_FIRED` verdict string (CI keys on `verdict`, §3.6). This exemption is checked ahead of, and removes from, the quadrant classification below; the quadrant table applies ONLY to the **constrained** condition subset (single-`ScalarRef`-vs-`Lit`). **VERDICT PRECEDENCE (r4/orchestrator): the exemption removes the deferred bit from quadrant classification but NEVER short-circuits the run — legs (a)/(c), leg (b) postconditions, and the constrained-subset quadrants are ALWAYS still evaluated for the same run, and any ERROR/FAIL/UNSATISFIABLE outcome from them takes precedence over `UNCONSTRAINED_PRECONDITION_FIRED` (which is then demoted to a `note` on the higher-severity verdict). A deferred-condition fire may only BE the verdict when the rest of the run is otherwise clean.**
    - **The 4-quadrant table (r3/fix-4, over the CONSTRAINED subset).** Let *host* = the `f32` host re-check over the constrained predicates, and *GPU* = whether any constrained-condition bit is set in `flag_words[0]`:

      | host re-check (constrained) | GPU `flag_words[0]` (constrained bits) | verdict | `reason.kind` | exit |
      |---|---|---|---|---|
      | **SATISFIED** | clean (0) | this run PASSES legs (a)+(b) | — | 0 |
      | **SATISFIED** | fired | **FAIL** | `precondition_check_miscompiled` (CPU/GPU disagree ⇒ an M3.17 lowering miscompile, surfaced HONESTLY — never blamed on the satisfier); counterexample names the scalars + disagreeing condition | 1 |
      | **UNSATISFIED** | fired | **ERROR** | `satisfier_unsound` (the satisfier emitted a value its own constrained predicate rejects, and the GPU agreed by firing) | 2 |
      | **UNSATISFIED** | clean (0) | **ERROR** | `satisfier_unsound_or_check_inert` (the satisfier emitted a violating input, yet NO flag fired — EITHER the satisfier is unsound OR the M3.17 check is missing/inert/miscompiled-to-never-fire; both are hard errors this totality catches) | 2 |

    - The finding is always reported loudly, never silently swallowed. (The umbrella diagnostic string, when the host re-check is somehow entirely unavailable, is the honest `"precondition_check_miscompiled_or_satisfier_unsound"`.)
  - Both words zero (Ok) AND the host re-check SATISFIED (top-left quadrant) ⇒ this run passes legs (a)+(b).
  - **Requires `--debug-oracle`** (opt-in). Without it, legs (a)+(c) still run on a release compile (no postcondition check) — a weaker but valid smoke fuzz. **Default: `--debug-oracle` ON only when the kernel has ≥1 lowered `DebugCheck` of kind `Post`** (otherwise it is a no-op and we skip the debug recompile). The `--debug-oracle`/`--no-debug-oracle` pair lets the user force it. **Inert-run note (r2/optimistic-minor): when `--debug-oracle` is forced ON but the kernel has zero lowered `Post` checks (all deferred, or none authored), leg (b) is a no-op; the report emits a `notes` entry `postcondition_oracle_inert` so a PASS is never mistaken for "postconditions were exercised" (mirrors §10's all-deferred case).**
- **(c) Determinism.** For a chosen run (the first successful one), dispatch the SAME input set **twice** and require **byte-identical** outputs (reuse `find_nondeterminism` from rewrite_verify.rs verbatim). A non-deterministic kernel on fixed input is a real defect. Reported as a `nondeterministic` counterexample. This is the M3.16 self-check pattern applied to a single kernel (not a rewrite pair).

**Anything beyond this triad is scope creep** and is explicitly NOT done: no golden/reference comparison, no cross-kernel equivalence, no perf assertion, no coverage metric.

### 3.3 The violated-precondition leg (IN SCOPE, opt-in `--violate`)

Validates the *checks themselves*, not the kernel: generate an input that **violates** one precondition (negate its interval — e.g. for `gt(n, 0)` pick `n = 0`), dispatch via `dispatch_debug_checked`, and **assert the corresponding `flag_words[0]` precondition bit fires** (`DebugCheckViolation.preconditions` names that condition). If it does NOT fire, the M3.17 lowering is broken ⇒ **FUZZ FAIL** (`precondition_check_did_not_fire`). Decision: **IN SCOPE** — it is nearly free (reuses the whole dispatch path), it closes the loop on "is the oracle real," and it exercises the satisfier's interval-negation. v1 violates **one** precondition per invocation; exhaustive negation over all conditions is deferred (§11).

**r2/W-1 — `--violate` scoped to non-size-coupled scalars (device-fault safety).** Violating a precondition can push a scalar to an extreme (e.g. `n = 0`, or a huge upper value); if that scalar is coupled to a buffer size or bounds a loop/index, the resulting dispatch can OOB-write and raise a *device fault* that PREEMPTS the very flag-readback AT-2899 asserts. **Rule (v1), two-tier:**
  1. **General conservative eligibility:** `--violate` picks the first lowerable `Pre` check whose scalar is **not** used in any buffer-index / bounds / dispatch-geometry expression AND is not a conventional element-count (a scalar the tool cannot prove geometry-independent is EXCLUDED — conservative-when-uncertain). Only provably geometry-independent scalars are eligible.
  2. **Shipped-fixture pin (explicit, removes Coder discretion):** for `precondition_saxpy` the violate target is **PINNED to `alpha`** — the width-independent f32 scale. `n` is EXCLUDED even though this particular body happens to index only by `gid(0)`: `n` is the declared element count (`@complexity(O(n))`), a size-coupled scalar by convention, and a fuzzer must not drive a count-scalar to an extreme on an arbitrary kernel. So **`alpha` yes / `n` no.** The violate input drives `gt(alpha, 0)` false via `alpha ≤ 0` (a widened/negated window), and AT-2899 asserts `flag_words[0]`'s bit for `gt(alpha,0)` fires.
If NO eligible scalar exists ⇒ usage ERROR (`nothing safely violable`), reported, not a silent no-op. **Documented residual:** on an arbitrary future kernel whose only precondition is on a size-coupled scalar, `--violate` may still return a `device_fault` outcome; that is an ACCEPTED (not FAIL) result and is recorded as such — the leg-(a) `device_fault` classification path itself ships DESIGNED-BUT-UNEXERCISED in v1 (no shipped fixture drives an intentional OOB, which would risk wedging the Lavapipe ICD).

### 3.4 The constraint satisfier (the ONE substantive new algorithm)

**Input:** `Vec<DebugCheck>` from HIR, filtered to `kind == Pre`. Each is `{ op: DebugCompareOp, ty: ScalarTy (U32|I32|F32), lhs: DebugOperand, rhs: DebugOperand }` where each operand is `ScalarRef{name,position}` or `Lit(i64)`.

**v1 handles the single-variable-vs-literal case** (exactly one operand is a `ScalarRef`, the other a `Lit`) — which is trivial interval arithmetic. Two-`ScalarRef` predicates (`gt(a, b)`, cross-scalar relational) are **not interval-solvable in v1** → the scalars stay unconstrained-by-that-predicate (generated within the default window) and a `note` is emitted (`relational_constraint_deferred`). Two-`Lit` predicates never reach here (HIR rejects them as ambiguous).

**Per-scalar accumulation** (grouped by `ScalarRef.name`):

Normalize each predicate so the scalar is the left operand. If the `ScalarRef` is on the RHS, flip the op: `gt(k,s)→ s<k`, `ge(k,s)→ s≤k`, `lt(k,s)→ s>k`, `le(k,s)→ s≥k`, `eq/ne` symmetric.

**Integer types (U32/I32) — exact, in `i128`** (start `[lo,hi]` = `ScalarTy::int_range()`):
- `s > k` ⇒ `lo = max(lo, k+1)`
- `s ≥ k` ⇒ `lo = max(lo, k)`
- `s < k` ⇒ `hi = min(hi, k-1)`
- `s ≤ k` ⇒ `hi = min(hi, k)`
- `s = k` ⇒ pin: `lo = hi = k` (and if the pin later conflicts ⇒ unsat)
- `s ≠ k` ⇒ add `k` to an exclusion set

**Unsatisfiability (conflicting constraints — detected, not swallowed):**
- `lo > hi` after intersection ⇒ **UNSATISFIABLE** (e.g. `gt(n,10)` ∧ `lt(n,5)`).
- an `eq` pin outside `[lo,hi]` or in the exclusion set ⇒ **UNSATISFIABLE** (e.g. `eq(n,3)` ∧ `ne(n,3)`).
- `[lo,hi]` is a single point that is excluded ⇒ **UNSATISFIABLE**.

**r3/C-1new — F32 IS THE ONLY DEBUG FLOAT TYPE; ALL float reasoning is in `f32`, NOT `f64`.** The M3.17 `DebugCheck.ty` for a float operand is **always `ScalarTy::F32`** (`ty.rs:23`, `hir.rs:157` — there is no f64 DebugCheck float). Therefore the satisfier's ENTIRE float pipeline — interval endpoints, open/closed adjustment, exclusions, representative-value pick, uniform draw, AND the §3.5 host re-check — is computed in **`f32`**. An `f64` interval is FORBIDDEN: an `f64` open-bound step or an `f64` re-derivation can land on a value that is NOT representable in `f32`, which after the std430 `f32` round-trip to the GPU becomes a DIFFERENT value than the one the satisfier reasoned about — silently re-opening exactly the endpoint-flake (M-1) and the CPU/GPU-disagreement (C-2) hazards this design closes. **Rule:** the value the satisfier proves and the value the host re-check evaluates are the SAME `f32` bit pattern that is std430-encoded into the push-constant buffer and dispatched (byte-identical); no computation ever widens to `f64`.

**Float type (F32) — interval in `f32` with open/closed flags.** `gt/lt` set open bounds, `ge/le` closed, `eq` pins, `ne` excludes the exact value (measure-zero — any other f32 satisfies). Unsat when `lo > hi`, or `lo == hi` with either bound open, or a pin outside the interval. Representative value: pin if pinned; else the interval midpoint (bounded, rounded to the nearest `f32`), or `lo + 1.0` / `hi − 1.0` (in `f32`) within the window for one-sided bounds. Float draws are seeded uniformly within the effective window (`f32` endpoints) and skip the (measure-zero) exclusions.

**r2/M-1 (RE-STATED IN F32 per r3/C-1new) — OPEN float bounds sample the STRICT `f32` INTERIOR.** A `gt/lt` bound is OPEN, but `rand`'s `gen_range(lo..hi)` is half-open `[lo, hi)` and CAN return exactly `lo`; for `gt(alpha, 0)` a draw of `0.0` makes the ORDERED `FOrdGreaterThan` compare FALSE, the precondition bit fires, and a SOUND satisfier gets mislabeled — flaking AT-2896 reproducibly for whichever `(seed, run)` lands on the endpoint. **Fix (all in `f32`):** when a float bound is OPEN, the sampler draws over the strict `f32` interior —
  - **open lower bound AT 0** (`gt(alpha, 0)`, the shipped-fixture case): the inclusive floor is **`f32::MIN_POSITIVE`** (the smallest normal positive `f32`), which is **FTZ-safe** — a denormal floor could be flushed to `0.0` on a flush-to-zero device and reintroduce the endpoint-flake, whereas `f32::MIN_POSITIVE` survives FTZ and still strictly satisfies `> 0`.
  - **general open bound** (open lower `> lo`, open upper `< hi`, `lo ≠ 0`): the inclusive floor is **`lo.next_up()`** (the smallest `f32` strictly greater than `lo`) and the inclusive ceiling is **`hi.next_down()`** — i.e. an `f32` nextafter, implemented as `f32::next_up()`/`f32::next_down()` (Rust 1.86+) or an explicit `f32`-bit-increment fallback (`f32::from_bits(x.to_bits() ± 1)` with sign handling). NEVER an `f64` nextafter.
  - CLOSED bounds keep `lo` / `hi` exactly.
The effective window's endpoints are adjusted by the SAME `f32` step before the uniform draw, so no draw can ever land on an excluded open endpoint. (Integer domains are already endpoint-exact via `k±1`; `ne`-float exclusions remain measure-zero-safe. This fix is specifically the open-BOUND draw, not the representative-value pick.)

**Value generation (per run `r`, seeded `StdRng::seed_from_u64(seed ^ scalar_position ^ r)`):**
- pinned ⇒ the pinned value every run.
- else draw within the **effective window** derived from `[lo,hi]` and `--scalar-window W` (default 256):
  - both bounds finite (from preconditions) ⇒ use `[lo,hi]` directly (already bounded).
  - lower-bounded only (`hi` == type max) ⇒ `[lo, lo + W]`.
  - upper-bounded only (`lo` == type min) ⇒ `[hi − W, hi]`.
  - unbounded (no precondition on this scalar, or only relational) ⇒ `U32:[0,W]`, `I32:[−W/2, W/2]`, `F32:[0,W]`.
  - integer draws skip exclusions (retry a bounded number of times, then fall to the nearest non-excluded value; the interval is proven non-empty by the unsat gate).

**Honest v1 limitation (documented, not hidden):** the satisfier does **not** reason about the semantic relationship between a scalar and buffer/dispatch sizes (it cannot know `n` is "the element count of buffer x"). The caller supplies `--buffer-sizes`/`--size` and `--workgroups` (fixed across runs, exactly like rewrite-verify); the caller is responsible for sizing buffers to cover the `--scalar-window`. If a fuzzed scalar drives an out-of-bounds access, the **leg-(a) no-fault oracle surfaces it honestly as a `device_fault`** (a real, reported outcome — not a hidden false pass). The shipped fixture (`precondition_saxpy.axc`) is unaffected: its body indexes purely by `gid(0)` and `n` bounds nothing, so fuzzing `n ∈ [1, 256]` is safe.

**Emitting push-constants:** for each run, write every scalar's chosen value into a `push_constant_total_bytes`-sized byte buffer at its `ScalarPushConstantSlot.offset` (std430, the exact layout codegen uses), little-endian per its `ScalarTy` width. Scalars with **no** precondition are fuzzed within the default window too (or take a caller `--push-constants-base64` base value if the future knob is added — deferred; v1 fuzzes them).

The satisfier is a **pure function** — `solve(checks: &[DebugCheck]) -> Result<Constraints, Unsat>` plus `sample(constraints, seed, run) -> Vec<ScalarValue>` — fully CPU-unit-testable with synthetic `DebugCheck` vectors (no GPU, no compile).

### 3.5 fuzz JSON schema

```json
{
  "verdict": "PASS",       // PASS | FAIL | UNSATISFIABLE | SKIPPED | UNCONSTRAINED_PRECONDITION_FIRED | ERROR   (FIRST key)
  "milestone": "M3.18",
  "kernel": "precondition_saxpy",
  "seed": 0,
  "runs_requested": 32,
  "runs_executed": 32,
  "debug_oracle": true,
  "violate_leg": false,
  "device": "NVIDIA RTX PRO 6000",     // null on CPU-only verdicts
  "constraints": [
    { "scalar": "n",     "ty": "u32", "interval": "[1, 257]",  "from": ["gt(n, 0)"] },
    { "scalar": "alpha", "ty": "f32", "interval": "(0, 256]",  "from": ["gt(alpha, 0)"] }
  ],
  "counterexample": null,   // present on FAIL:
  // { "run": 7, "scalars": {"n": 3, "alpha": 512.0},
  //   "reason": "postcondition_violation",   // | device_fault | nondeterministic
  //                                          // | precondition_check_did_not_fire (under --violate)
  //                                          // | precondition_check_miscompiled (r2/C-2: GPU pre-bit fired
  //                                          //   on a HOST-satisfied input ⇒ M3.17 miscompile, not tool bug)
  //   "detail": { "postconditions": ["lt(alpha, 1000)"] } }
  "reason": null,           // present on non-PASS: { "kind": "...", "detail": {...} }
                            // reason.kind ∈ { gpu_unavailable | coopmat_unsupported | device_feature_unsupported
                            //   | satisfier_unsound (r2/C-2: constrained-condition HOST-unsatisfied + GPU-fired ⇒ tool bug, ERROR)
                            //   | satisfier_unsound_or_check_inert (r3/fix-4: constrained HOST-unsatisfied + GPU-CLEAN ⇒
                            //       satisfier unsound OR M3.17 check missing/inert, ERROR — the 4th quadrant)
                            //   | precondition_check_miscompiled_or_satisfier_unsound (host re-check unavailable)
                            //   | unconstrained_precondition_fired (r3/C-2new: a DEFERRED relational condition's bit fired;
                            //       SKIPPED-class, exit 0 — the satisfier made no promise, NOT a bug)
                            //   | unsatisfiable | compile_failed | usage | io }
  "host_recheck": null,     // r3/fix-4: UNCONDITIONAL per run — {scalars_std430_f32_bits, gpu_flag_words0,
                            //   host_constrained_result, host_quadrant} (the f32 re-check on the byte-identical value sent)
  "notes": []
}
```

- `verdict` first key (same technique as `VerifyReport`).
- **r3/C-1new (stated here as in §3.4): the precondition discriminator's host re-check is `f32`, on the std430-decoded bytes ACTUALLY SENT.** The host re-check evaluates every Pre predicate in `f32` (the only DebugCheck float type) on the byte-identical `f32`/`i32`/`u32` value decoded back out of the push-constant buffer that was dispatched — NEVER an `f64` re-derivation of "what the value should have been." This is what makes the CPU-vs-GPU `precondition_check_miscompiled` discrimination sound: both sides evaluate the identical bit pattern, so any disagreement is a genuine M3.17 lowering fault and not an `f32`↔`f64` rounding artifact.
- **The discriminator is TOTAL and DEFER-EXEMPT (r3/fix-4 + r3/C-2new).** The host re-check runs **unconditionally on every run**; the full 4-quadrant table lives in §3.2(b). A fired bit attributable to a **deferred** (two-`ScalarRef` relational) condition is EXEMPT and yields the `UNCONSTRAINED_PRECONDITION_FIRED` verdict (below), checked BEFORE the quadrant table; the quadrants apply only to the **constrained** subset.
- **PASS** ⇒ all runs cleared legs (a)+(b)+(c) [+ the violate leg if `--violate`], with the host re-check in the top-left (host-SATISFIED + GPU-clean) quadrant on every run.
- **FAIL** ⇒ a counterexample was found: postcondition violation / device fault / nondeterminism / precondition-check-did-not-fire (under `--violate`) / **`precondition_check_miscompiled`** (r2/C-2 + r3/fix-4: a constrained precondition bit fired on an input the HOST `f32` re-check says is SATISFIED ⇒ CPU/GPU disagree ⇒ M3.17 check miscompile, surfaced honestly, NOT blamed on the satisfier). **Exit 1.**
- **UNSATISFIABLE** ⇒ conflicting preconditions; no input can be generated (a genuine finding about the *spec*, semantically distinct from a found kernel bug). **Exit 3 (r2/warning: distinct from FAIL's exit 1)** — a spec-fact vs a code-fact must not be exit-indistinguishable. Downstream CI keys on `verdict` regardless (see §3.6).
- **SKIPPED** ⇒ GPU unavailable (`reason.kind = gpu_unavailable`) OR coopmat/device-feature unsupported (typed-skip, reusing the rewrite-verify `CoopMatUnsupported`/`DeviceFeatureUnsupported` mapping). Exit 0.
- **UNCONSTRAINED_PRECONDITION_FIRED** (r3/C-2new) ⇒ a `flag_words[0]` bit fired for a DEFERRED relational condition the satisfier never constrained. **SKIPPED-class, exit 0**, with a loud `note` listing the exempt condition(s) + sampled scalars, `reason.kind = unconstrained_precondition_fired`. Explicitly **NOT** `satisfier_unsound` and **NOT** miscompile-suspect — the satisfier honestly disclaims the condition (§3.4 `relational_constraint_deferred`), so its firing is expected, not a defect. (Justification for exit 0 in §3.2(b).)
- **ERROR** ⇒ compile failure, **`satisfier_unsound`** (r2/C-2: a constrained precondition bit fired AND the HOST `f32` re-check ALSO rejects the sampled value ⇒ genuine tool bug), **`satisfier_unsound_or_check_inert`** (r3/fix-4: the HOST `f32` re-check rejects a constrained input yet NO bit fired — satisfier unsound OR the M3.17 check is missing/inert), the honest umbrella `precondition_check_miscompiled_or_satisfier_unsound` when the host re-check is unavailable, or usage/IO. Exit 2.
- **SEVERITY ORDERING (r4/orchestrator, binding for both per-run and aggregate report verdicts): `ERROR > FAIL > UNSATISFIABLE > UNCONSTRAINED_PRECONDITION_FIRED > SKIPPED > PASS`.** A single run (and the aggregate report) takes the HIGHEST-severity outcome observed; `UNCONSTRAINED_PRECONDITION_FIRED` never masks a same-run device fault, postcondition violation, nondeterminism, miscompile, or satisfier error — when out-ranked it is demoted to a warning `note` (still emitted, never lost). Exit code follows the winning verdict.

### 3.6 fuzz exit codes

`exit_code_for_fuzz`: `PASS | SKIPPED | UNCONSTRAINED_PRECONDITION_FIRED → 0` (r3/C-2new: the last is SKIPPED-class — a deferred condition firing is not a defect), `FAIL → 1`, `ERROR → 2`, **`UNSATISFIABLE → 3` (r2: distinct from FAIL, so a conflicting-precondition *spec* finding is not conflated with a found *code* bug at the exit-code level).** **CI MUST key on the `verdict` JSON field, not the exit code alone** — FAIL and UNSATISFIABLE are already exit-distinct after r2, and `UNCONSTRAINED_PRECONDITION_FIRED` shares exit 0 with PASS/SKIPPED yet is a distinct `verdict` string a strict CI can gate on; the authoritative discriminator remains `verdict`; no consumer branches on exit code alone (confirmed against the rewrite-verify call sites). This extends the rewrite-verify convention (which collapsed the two) with the UNSATISFIABLE=3 code (UNCONSTRAINED_PRECONDITION_FIRED reuses 0).

## 10. Edge cases

- Kernel with **no preconditions**: fuzz still runs (all scalars in the default window; legs (a)+(c); leg (b) is a no-op unless `--debug-oracle` forces it and there are Post checks). Not an error.
- Kernel with **no scalars at all** (pure buffer kernel): fuzz varies buffer inputs only (seeded fills); satisfier returns empty constraints; legs (a)+(c) run.
- **`--violate` with no lowerable precondition**: usage ERROR (nothing to violate) — reported, not a silent no-op.
- **`--runs 0`**: usage ERROR (`runs` must be ≥ 1).
- **`--debug-oracle` on a kernel with only DEFERRED postconditions** (all `PostconditionNotLowerable`) OR with **zero lowered `Post` checks at all**: a `notes` entry `postcondition_oracle_inert` warns "postcondition oracle inert (no lowered Post check exercised)"; legs (a)+(c) still run. (r2/optimistic-minor: guarantees a PASS is never mistaken for "postconditions were checked" when leg (b) was a no-op.)
- **coopmat/shared kernel**: requires explicit `--workgroups` (reuse the rewrite-verify preflight rule); missing ⇒ usage ERROR.
- **`@precondition(true)`** (trivial): contributes no interval, no bit — satisfier ignores it (it is a `PreconditionTrivial`, not a `DebugCheck`).
- **UNSATISFIABLE takes precedence over GPU probe**: detected on CPU before any Vulkan work, so it reports deterministically in CI without a GPU (AT-2893, exit 3).
- **Deferred relational precondition fires (r3/C-2new)**: a two-`ScalarRef` `gt(a,b)` bit fires because the satisfier sampled its scalars in the default window (it deferred the constraint). The fuzzer attributes the fired bit to that deferred condition (via `DebugCheck.bit`) and emits `UNCONSTRAINED_PRECONDITION_FIRED` (SKIPPED-class, exit 0, warning note) — NOT `satisfier_unsound`, NOT `precondition_check_miscompiled`. The satisfier honestly disclaimed the condition, so its firing is expected.
- **Constrained input violates yet no bit fires (r3/fix-4, 4th quadrant)**: the unconditional `f32` host re-check rejects a constrained sampled value but `flag_words[0]` is clean ⇒ `satisfier_unsound_or_check_inert` (ERROR, exit 2) — either the satisfier emitted a violating input OR the M3.17 check is missing/inert. The totality of the discriminator (host re-check runs every run) is what surfaces this otherwise-invisible case.
- **f32-only float reasoning (r3/C-1new)**: no float value the satisfier proves, samples, or re-checks is ever computed in `f64` — the proved value, the std430-encoded value sent, and the host-re-checked value are one byte-identical `f32` bit pattern, so no `f32`↔`f64` rounding artifact can masquerade as a miscompile or an endpoint-flake.

## r3-changelog (Architect revision, FINAL cycle — addressing r2 pessimistic NEEDS_REVISION + optimistic line-item)

**Architecture, scope, and AT range UNCHANGED (AT-2881..2899).** Every r3 edit is spec-text only (no new file, no visibility change, no API-signature change beyond the discriminator's internal shape). The five fixes:

- **C-1new (f32 precision — §3.4 AND §3.5, stated prominently in both).** F32 is the ONLY DebugCheck float type (`ty.rs:23`, `hir.rs:157`); the satisfier's entire float pipeline AND the host re-check are now computed in **`f32`**, never `f64`. Open lower bound AT 0 → floor at **`f32::MIN_POSITIVE`** (FTZ-safe, survives flush-to-zero). General open bounds → **`f32::next_up()`/`next_down()`** (or an `f32`-bit-increment fallback), never an `f64` nextafter. The host re-check evaluates the predicate on the **std430-decoded `f32` bytes actually sent to the GPU** (byte-identical value), never an `f64` re-derivation — this is what makes `precondition_check_miscompiled` discrimination sound (no `f32`↔`f64` rounding artifact).
- **C-2new (deferred-condition exemption).** Two-`ScalarRef` relational preconditions ARE lowered and CAN fire (`lower.rs:587`) but the satisfier DEFERS them. The discriminator now attributes each fired `flag_words[0]` bit to its condition (`DebugCheck.bit`) and, BEFORE the quadrant table, EXEMPTs any bit belonging to a deferred/unconstrained condition ⇒ new verdict **`UNCONSTRAINED_PRECONDITION_FIRED`**, **SKIPPED-class, exit 0** with a warning note listing the condition(s) + scalars, `reason.kind = unconstrained_precondition_fired`. **Decision & justification:** exit 0 (SKIPPED-class) chosen because the deferral is a documented, honest v1 limitation (`relational_constraint_deferred`, §3.4) the satisfier openly disclaims — its firing is neither `satisfier_unsound` (no promise broken) nor miscompile-suspect (the check fired correctly on an unconstrained input); a strict CI can still gate on the distinct verdict string (CI keys on `verdict`). Folded into AT-2892 + a new §10 edge case.
- **AT-2893 (fix-3, the optimistic reviewer's line-item): exit 1 → exit 3.** Made §3.5, §3.6, and the AT table mutually consistent (UNSATISFIABLE = exit 3 everywhere).
- **Discriminator totality (fix-4): the host re-check is now UNCONDITIONAL (all four host×GPU quadrants defined).** Exact table (constrained-condition subset; deferred-exemption applied first):

  | host re-check (constrained) | GPU `flag_words[0]` (constrained bits) | verdict | `reason.kind` | exit |
  |---|---|---|---|---|
  | SATISFIED | clean (0) | run PASSES (a)+(b) | — | 0 |
  | SATISFIED | fired | FAIL | `precondition_check_miscompiled` | 1 |
  | UNSATISFIED | fired | ERROR | `satisfier_unsound` | 2 |
  | UNSATISFIED | clean (0) | ERROR | `satisfier_unsound_or_check_inert` | 2 |

  The 4th quadrant (host-unsat + GPU-clean) is the r3 addition — it catches the *inert/missing-check* case (a check that should have fired but did not) as well as an unsound satisfier, labeled `satisfier_unsound_or_check_inert`. Folded into AT-2891.
- **AT-2897 (fix-5): PROVEN-FIRING triple pinned at implementation time.** The Coder measures once — with a widened window (`--scalar-window ≥ 1024`) confirm a run's `alpha` draw lands in `[1000, window]` and the postcondition fires — then PINS that exact `(seed, scalar_window, runs)` triple as AT constants. Seeded deterministic sampling makes the pinned triple stable across machines/CI; a toolchain RNG-stream change ⇒ re-measure and re-pin. The AT is thus a deterministic assertion, not a probabilistic one.

**Nothing else moved:** verify C1–C5, the fuzz oracle triad (a/b/c), the interval satisfier's integer path, the `--violate` leg (§3.3, `alpha`-pin), the CLI surface, the reuse-over-duplication discipline, the files-to-create/modify list, and the zero-compiler-change gate all STAND from r2. §12 total nudged ~1330 → ~1355 (the discriminator helper grew for the f32 std430 re-check + 4-quadrant totality + defer-exemption); cap ~1700 unchanged.
