## Item 1 — EB.3: `axc bench` CLI subcommand (~150–200 LOC)

**Goal.** A discoverable wrapper over the existing `cargo bench -p axc-driver` flow so
users don't have to remember the cargo incantation or the `AXC_BLESS_BASELINES=1` env.

### Design

Add a new `Command::Bench` variant to the `Command` enum in `cli.rs`, following the
existing subcommand pattern (clap derive, doc-comment help):

```rust
/// Run the AXIOM-Compute benchmark suite (wrapper over `cargo bench -p axc-driver`).
///
/// Examples:
///   axc bench                       # run all bench groups
///   axc bench --filter cpu_saxpy    # run only benches whose name matches `cpu_saxpy`
///   axc bench --bless               # run all + promote candidate → baselines.json
///
/// NOTE: run the INSTALLED/built `axc` binary, NOT `cargo run -p axc-driver -- bench`.
/// `axc bench` spawns an inner `cargo bench` that needs the workspace target-dir build
/// lock; launching it via `cargo run` (same target dir) makes the inner cargo block
/// forever on the lock the outer `cargo run` holds → a self-deadlock.
Bench {
    /// Only run benches whose Criterion name contains this substring.
    ///
    /// Passed through to `cargo bench -p axc-driver -- <FILTER>` (Criterion's
    /// positional name filter).
    #[arg(long, value_name = "NAME")]
    filter: Option<String>,

    /// Promote the measured candidate to `.pipeline/benchmarks/baselines.json`
    /// for THIS machine's key (sets `AXC_BLESS_BASELINES=1` for the child).
    #[arg(long)]
    bless: bool,
},
```

### Pure command-builder (the testable seam)

To keep the subcommand testable **without executing cargo** (running `cargo bench`
inside `cargo test` is slow, GPU-touching, and recursive), factor the argv/env
construction into a pure function in `lib.rs`:

```rust
/// Build the child-process invocation for `axc bench`.
///
/// Returns `(program, args, env_overrides)`.  Pure — does NOT spawn.  This is the
/// unit-test seam (AT-2828) so the argv/env mapping is verified without running cargo.
pub fn build_bench_command(
    filter: Option<&str>,
    bless: bool,
) -> (String, Vec<String>, Vec<(String, String)>)
```

Mapping (exact, test-pinned):
- `program = "cargo"`.
- base `args = ["bench", "-p", "axc-driver"]`.
- if `filter = Some(f)`: append `["--", f]` (Criterion positional filter after the `--`).
- if `bless`: `env_overrides = [("AXC_BLESS_BASELINES".into(), "1".into())]`; else `[]`.

### main.rs handler

`Command::Bench { filter, bless }` → call `build_bench_command`, then
`std::process::Command::new(program).args(args).envs(env_overrides)` with **inherited**
stdio (child bench output streams straight to the user's terminal), `.status()`, and:
- cargo-not-found (`io::ErrorKind::NotFound`) → `miette::miette!("axc bench: `cargo` not found on PATH — install a Rust toolchain")`.
- child exit non-zero → propagate as a miette error carrying the exit code (so `axc bench` exits non-zero when a bench/gate fails).
- happy path → `Ok(())`.

The spawn helper (`run_bench`) lives in `lib.rs`/`main.rs`; it is **not** unit-tested
(it shells out) — only `build_bench_command` is. This is an acceptable seam: the
mapping is the logic, the spawn is a thin `std::process` call.

**r2 addition (pessimistic-review warning: EB.3 nested-cargo deadlock).** The spawn
handler's doc-comment (and the `Bench` clap help above) MUST carry a one-line note:
run the **installed/built `axc` binary**, not `cargo run -p axc-driver -- bench`. The
inner `cargo bench` acquires the workspace target-dir build lock; if `axc` was itself
launched via `cargo run` (same target dir), the inner cargo blocks forever on the lock
the outer `cargo run` holds — a self-deadlock. Normal installed-binary usage is fine;
the note prevents the footgun.

### Errors
`DriverError` is not extended — `axc bench` failures surface as `miette` errors from the
`main.rs` handler (consistent with `axc mcp`'s error style).

### Tests
- **AT-2826** (parse, default): `Cli::parse_from(["axc","bench"])` → `Command::Bench { filter: None, bless: false }`.
- **AT-2827** (parse, flags): `["axc","bench","--filter","cpu_saxpy","--bless"]` → `filter: Some("cpu_saxpy"), bless: true`.
- **AT-2828** (builder, pure): `build_bench_command(None,false) == ("cargo", ["bench","-p","axc-driver"], [])`; `build_bench_command(Some("cpu_saxpy"), true) == ("cargo", ["bench","-p","axc-driver","--","cpu_saxpy"], [("AXC_BLESS_BASELINES","1")])`.
- **AT-2829** (discoverability): render `Bench`'s clap help (`Command::augment_subcommands`/`Cli::command()`); assert it mentions `--filter`, `--bless`, and the word `baseline`. Guards that help text stays useful.

## Item 2 — `strip_strategy_annotation_block` robust fix (medium)

**Bug (M3.14 footgun).** `crates/axc-driver/src/lib.rs:~299` does
`source.find("@strategy")`, which latches onto the **first substring** anywhere —
including inside a `//` line comment or inside `@intent("… @strategy …")` prose. When
the decoy occurrence is not followed by `{`, the function returns the source
**unchanged** (the call-form guard), so the *real* `@strategy { … }` block is never
stripped → HIR lowers the residual `?[…]` candidates → codegen trips
`UnresolvedStrategyHole`. M3.14 dodged it by rewording a comment.

### Fix (robust, minimal, driver-only — reuses the compiler's own lexer)

The lexer already skips comments and string literals and emits
`TokenKind::Annotation(String)` (carrying the bare name, e.g. `"strategy"`) with a
byte-`Span`. A `@strategy` inside a comment produces **no** token; a `@strategy` inside
an `@intent("…")` string is part of a **string literal**, not an `Annotation` token.
So the robust anchor is: the first `Annotation("strategy")` token's span.

Rewrite `strip_strategy_annotation_block` to:
1. `let (tokens, _errs) = axc_lexer::tokenize(source);` (dep already present — `cli.rs`/`main.rs` `Lex` uses it; `Cargo.toml:199` `axc-lexer`).
2. Find the **first** `Spanned<Token>` whose kind is `TokenKind::Annotation(name)` with `name == "strategy"`.
3. Derive `at_pos` = the byte offset of the `@` sigil. The Coder MUST verify against the real lexer whether `Annotation`'s span includes the `@`: assert `source[at_pos..].starts_with("@strategy")`; if the span starts at the name, back up one byte to the `@`. Pin this with a debug_assert + AT-2832.
4. From `at_pos`, keep the **existing** logic verbatim: skip whitespace, require the next non-ws char is `{` (else return unchanged — preserves the `@strategy(...)` call-form escape hatch, AT-2834), then the existing depth-tracking brace scan for the matching `}`, then splice `before + after`.
5. If no `Annotation("strategy")` token exists → return source unchanged (same as today).

Update the doc-comment to state the anchor is now lexer-token-based (comment/string
safe), and delete the stale "finds the first `@strategy` in the text" wording.

**Scope discipline:** this is a driver-internal change. No lexer/parser/HIR/codegen
change. Signature (`pub(crate) fn(&str) -> String`) unchanged. `substitute_strategy_holes`
Pass-1 (the `?name` replace) is untouched.

### Tests (adversarial fixtures + corpus regression anchor)
Test file: extend `crates/axc-driver/tests/strategy_saxpy_autotune.rs` or a new
`strip_strategy_robust.rs`. Fixtures are inline `&str`.

- **AT-2830** (line-comment decoy — the real footgun): source = `// tune @strategy here\n@strategy { x: ?[1] }\n@kernel …`. After strip: result contains **no** `@strategy {`, the `?[` candidate list is gone, and the comment line + kernel body survive. (Naive `find` would latch the comment, see ` here` ≠ `{`, and return unchanged — bug reproduced then fixed.)
- **AT-2831** (`@intent` prose decoy before the block): source = `@intent("explores @strategy space")\n@strategy { x: ?[1] }\n@kernel …`. After strip: no residual `@strategy {`; the `@intent(...)` line (including its `@strategy` prose) is preserved verbatim.
- **AT-2832** (real block alone, behavior preserved): a single `@strategy { rb_m: ?[2] }` with no decoy → stripped exactly (byte-identical to `source` minus that span); asserts the `@`-sigil offset is correct.
- **AT-2833** (no `@strategy`): source unchanged (identity).
- **AT-2834** (call-form / non-brace): `@strategy(foo)` (annotation followed by `(`) → unchanged (the `{`-guard escape hatch still holds).
- **AT-2835** (corpus regression anchor — MUST NOT change behavior): a test-local `naive_strip_reference(&str) -> String` reproduces the OLD `source.find("@strategy")` algorithm verbatim; then for **every** `examples/*.axc` containing `@strategy`, assert `strip_strategy_annotation_block(src) == naive_strip_reference(src)` (the load-bearing "identical before/after" equality — proves zero behavior change on the real corpus; this half is correct and MUST NOT be scoped) **and** the result carries no residual **live** `@strategy {` — where "live" is checked over **non-comment lines only**, exactly mirroring the existing AT-1576 precedent at `crates/axc-driver/src/lib.rs:711-713` (`src.lines().filter(|line| !line.trim_start().starts_with("//")).any(|line| line.contains("@strategy"))`).
  > **r2 correction (pessimistic-review critical #1, VERIFIED by the architect):** the r1 premise "no shipped example has a decoy" was FALSE. `examples/matmul_f32_tiled.axc:13` is literally `// The former @strategy { tile_m: ?[1,2,4], tile_n: ?[1,2,4] } holes were REMOVED` — a **brace-form `@strategy {` inside a `//` comment**. The lexer-based strip correctly leaves it untouched (comment → no `Annotation` token), so the equality half passes; but an unscoped `result.contains("@strategy {")` residual check would then FAIL on this file, shipping a RED gate. Scoping the residual clause to non-comment lines (as AT-1576 already does for this exact file) resolves it without weakening the equality half. Do NOT apply the non-comment filter to the `== naive_strip_reference` equality — only to the residual `@strategy {` clause.

## Item 4 — AT-103 golden full-bytes upgrade (cheap — INCLUDED)

**Current.** `crates/axc-driver/tests/compile_empty_kernel.rs` (labeled AT-1) validates
only the **first 3 header words** against `tests/fixtures/empty_kernel.spv.expected_header.txt`
plus a determinism/no-debug-opcode guard. It does **not** pin the full body.

**Why cheap + safe.** `compile_file` → `compile_source_with_meta` → `emit_module_bytes`
(`lib.rs:126`, `CodegenOptions::default()`) with **no spirv-opt pass** — codegen output
is byte-deterministic (the project asserts byte-identity across milestones everywhere).
A committed full-body golden is stable and version-independent.

### Design
1. Commit `tests/fixtures/empty_kernel.spv.golden` — the exact bytes of
   `compile_file(examples/empty_kernel.axc)`. Generate once via a documented one-liner
   recorded in the fixture's sibling `.md`/header comment and in the test:
   `axc compile examples/empty_kernel.axc -o tests/fixtures/empty_kernel.spv.golden`
   (regen instructions in the test doc-comment so a legitimate codegen change has a
   clear re-bless path).
2. In `compile_empty_kernel.rs`, after the existing header + spirv-val checks, add a
   strict full-byte comparison: `assert_eq!(spv_bytes, golden_bytes)` with a message
   pointing at the regen command. Keep the existing header-fixture + spirv-val checks.
   **r2 addition (pessimistic-review warning: golden re-bless trigger):** the mismatch
   panic text (and the test doc-comment) MUST name the expected legitimate cause of a
   golden change — **"a codegen or `rspirv` dependency change (e.g. an `rspirv`/codegen
   bump in `Cargo.lock` that shifts SPIR-V ID allocation)"** — so a future toolchain bump
   reads as "re-bless via the documented one-liner", not "mystery regression". Within a
   fixed rustc + `Cargo.lock` the golden is byte-stable (no spirv-opt, generator word
   force-set to 0), so any change beyond a codegen/rspirv bump is a real regression.

### Test
- **AT-2838**: emitted empty-kernel SPIR-V is **byte-identical** to the committed golden;
  on mismatch, the panic message names **both** the regen command **and** the expected
  legitimate cause ("a codegen or `rspirv` dependency change"). (Strict — determinism is a
  project invariant, so this is a real guard, not best-effort.)
