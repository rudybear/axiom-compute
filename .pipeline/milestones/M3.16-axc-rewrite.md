## 1. Thesis framing (why this is THESIS-CORE, not a perf re-open)

The project's differentiator (CLAUDE.md, DESIGN.md §1) is: *LLMs rewrite kernels at the source level today, but the optimization intent is implicit, leaving rewrites vulnerable to reward-hacking and silent correctness regressions. AXIOM-Compute makes the compiler **verify** what the LLM claims.* The architecture diagram lists the **self-optimize loop** ("LLM reads → proposes rewrite → benchmark → iterate") as a first-class component. `@strategy` holes (M2.3) already cover *parameter* tuning. FG.1 is the missing **structural** half: the LLM rewrites the kernel *body* (different loop nest, different memory-access pattern), and the compiler machine-checks that the rewrite is observationally equivalent to the original.

**This milestone is INFRASTRUCTURE (the verification mechanism), not a performance milestone.** M3.13 concluded the autonomous NVIDIA Q4_K_M performance campaign (the residual 2.39× is the portable-coopmat tax). M3.16 does **not** re-open that; it builds the *reusable A-vs-B differential-correctness harness* that any kernel, any vendor, any future rewrite (agent-proposed or human) is checked through. Its value is the anti-reward-hacking gate, usable independent of whether any given rewrite is faster.

## 2. The central design decision: verify, don't generate

The ROADMAP FG.1 sketch names an MCP tool `propose_rewrite(source, hint) -> rewritten_source`. **This spec deliberately deviates: we ship `verify_rewrite(original, rewritten) -> verdict`, not `propose_rewrite`.** Justification:

1. **The MCP server has no model-call capability today** and must not gain one. It is a JSON-RPC-2.0 *stdio* bridge (`crates/axc-driver/src/mcp/`) with no network/HTTP/model client. Adding an LLM client would balloon scope far past ~2000 LOC, add a network dependency and API-key handling to the compiler, and make the "compiler" non-deterministic.
2. **Putting generation inside the verifier breaks the thesis.** The whole anti-reward-hacking claim is that *the compiler is an independent oracle that checks the agent's claim.* If the same component both generates and verifies, the independence is gone. The agent (the LLM already driving the MCP session — Claude, in this project's pipeline) IS the generator; it proposes both `original` and `rewritten` and the tool returns a machine-checked verdict.
3. **The verifiable primitive is the value.** A pure `verify` function is deterministic, CI-testable, and vendor-agnostic. `propose` is not testable without a live model.

Consequently the deliverable is a **two-layer interface over one shared verification core**:

- **Layer 0 — the core** (`crates/axc-driver/src/rewrite_verify.rs`): a pure orchestration function `verify_rewrite(req, vk: Option<&VulkanContext>) -> VerifyReport`. No LLM, no I/O beyond reading the two sources. Reused verbatim by both layers above it.
- **Layer 1 — the CLI primitive** (`axc rewrite-verify <original.axc> <rewritten.axc> [--tol …] …`): the verifiable, LLM-free, CI-runnable command. This is the load-bearing deliverable.
- **Layer 2 — the MCP tool** (`verify_rewrite`): a thin JSON-RPC wrapper over the core, exposed to the agent alongside the existing 6 tools. The agent supplies both sources; the tool returns the verdict.

**Non-goal (explicit):** `propose_rewrite` / any in-compiler LLM call, and any prompting/iteration loop. Those live in the *agent*, which calls `verify_rewrite` repeatedly. Documented in §9.

## 3. Verification harness — the core deliverable

### 3.1 Pipeline (identical for both inputs, then differential compare)

Given `original` and `rewritten` source strings and a `VerifyRequest`:

1. **Compile both.** `compile_source_with_assignments(src, &assignments)` → `(spirv_bytes, KernelMetadata)` for each. (Optional shared `assignments` map lets a rewrite carry the same `@strategy` resolution as the original; default empty.) A compile error on *either* → verdict `FAIL`, `stage: "compile"`, side (`original`/`rewritten`), and the aggregated lex/parse/hir counts. **A non-compiling rewrite is a legitimate verification outcome, not an RPC/CLI error.**
2. **spirv-val both.** Reuse `mcp::tools::compile_variant::validate_spirv(&bytes)`. Rejection → verdict `FAIL`, `stage: "spirv_val"`, side, validator message.
3. **Interface gate (anti-cheat, CPU-only — §4).** `diff_interface(&meta_orig, &meta_rewritten)`. Any structural signature difference → verdict `REJECT`, `stage: "interface"`, with the specific `InterfaceMismatch`. This runs *before* any GPU work, so signature cheats are caught on CI without a GPU.
4. **Request-completeness preflight (CPU-only, metadata-driven — r2/WARN-1 + CRIT-1).** Runs *before* GPU work, so it is CI-reachable without a device. Two checks against the (identical) `KernelMetadata`:
   - If either kernel has `coopmat.is_some()` or `shared_memory_bytes > 0` and the request did **not** supply explicit `workgroups` → verdict `ERROR`, `stage: "preflight"`, `reason.kind: "workgroups_required"`. (`derive_workgroups` is element-wise-1-D-only; a wrong shared/coopmat grid must be a hard ERROR, never a silent partial-coverage pass.)
   - If `binding_plan.scalars` contains any `f32`/`f16` scalar and no push-constants were supplied → verdict `ERROR`, `stage: "preflight"`, `reason.kind: "push_constants_required"` (the alpha=0 annihilation guard — §3.2/CRIT-1).
   Element-wise kernels with integer-only (or no) scalars and a derivable grid pass this step. Workgroups are resolved **once** here and used for every dispatch below (legal because the interface gate proved `workgroup_size` matches).
5. **GPU availability.** If `vk` is `None` (no ICD / `AXC_ENABLE_GPU_TESTS` unset / probe failed): the CPU gates (1–4) have already passed, so emit verdict `SKIPPED`, `stage: "dispatch"`, `reason: "gpu_unavailable"`. This is a first-class outcome (Lavapipe/CI without a compute device), **not** a failure — mirrors the project's typed-skip discipline.
6. **Input generation (§3.2).** Build one deterministic input set (well-conditioned float fills; raw bytes for integer/packed buffers) and feed **the identical bytes to all dispatches below.**
7. **Determinism self-check (r2/WARN-2).** Dispatch the **ORIGINAL twice** with identical inputs/grid/push-constants. If the two original output sets are not bit-identical → verdict `NONDETERMINISTIC_ORACLE`, `stage: "self_check"`, `reason.kind: "original_nondeterministic"`, with the disagreeing buffer stats. This is **neither PASS nor FAIL for the candidate** — the original is not a usable oracle (atomics / unordered subgroup ops / uninitialized shared reads), so no verdict can be rendered against the rewrite. One extra dispatch; closes both the flaky-false-FAIL and the masking-false-PASS holes. `prepare_kernel_checked` / `dispatch_handle` errors here follow the §5 preflight/dispatch mapping (original side).
8. **Dispatch rewritten.** `vk.prepare_kernel_checked(words, &meta.binding_plan, meta.push_constant_total_bytes, &meta.entry_point, meta.coopmat.as_ref(), &meta.kernel_name, meta.shared_memory_bytes)` then `vk.dispatch_handle(&handle, workgroups, &input_refs, &output_sizes, &push_constants)`. `CoopMatUnsupported` / `DeviceFeatureUnsupported` on either kernel → verdict `SKIPPED` (typed-skip). Other `prepare`/`dispatch` `DispatchError` (e.g. `shared_memory_bytes` over `maxComputeSharedMemorySize`, unsupported binding): on the **rewritten** side → `FAIL`, `stage: "preflight"`, `reason.kind: "preflight_fail_rewritten"` (an unrunnable rewrite fails verification); on the **original** side → `SKIPPED`/`infra_error` by class (device incapacity, not a candidate verdict). Never panic, never lump into `coopmat_unsupported`. (§4.1 keeps `shared_memory_bytes` un-gated at the interface layer precisely so a rewrite *may* grow it — this is where an over-grown rewrite is caught.)
9. **Differential compare (§3.3).** For each output buffer, element-wise compare the **rewritten** run vs the **first original** run under the verifier-owned `TolerancePolicy`. Any buffer that diverges → verdict `FAIL`, `stage: "output"`, per-buffer divergence stats. All within tolerance → verdict `PASS`.

> **Shared-oracle-bug blindness (oracle honesty, r2).** Differential testing renders equivalence *relative to the original*: a rewrite that triggers the SAME driver/hardware bug as the original passes undetected. This is intrinsic to A-vs-B and is documented in §10 as a known limitation, not a defect of this harness.

**The original kernel IS the oracle.** No CPU reference implementation is needed or written — this is a differential (A-vs-B) check, which is exactly why it generalizes to *any* kernel without per-kernel oracle registration (the limitation that makes `bench_variant`'s `pick_cpu_reference` narrow).

### 3.2 Input-generation policy

Builds on `bench_variant`'s approach, with an r2 correction for float buffers (raw random bytes reinterpreted as f32/f16 are predominantly NaN/Inf/denormal — see CRIT-3):

- **Buffer inputs — element-type-dispatched fill (r2/CRIT-3):**
  - **Float element buffers (`f32`/`f16`, per `binding_plan`):** a **well-conditioned, finite, deterministic** fill — seeded uniform in `[-1, 1]`. Formula, per element `e` of buffer at binding index `b`:
    `rng_b = StdRng::seed_from_u64(seed ^ b)` (same seed derivation as `seeded_inputs`); draw `u: u32 = rng_b.next_u32()`; value `v = (u as f64 / u32::MAX as f64) * 2.0 - 1.0` (⇒ `v ∈ [-1, 1]`); store as `f32` (`v as f32`), or for `f16` buffers round `v as f32` to `f16` via the existing half-float path. This is denormal/NaN/Inf-free by construction, so the differential bit-exact compare never faces NaN-payload ambiguity or two-different-NaN-positions divergence.
  - **Integer / packed-quant buffers (`u8`/`u32`/packed Q4_K etc.):** raw byte fill via the existing `seeded_inputs(&sizes, seed)` (`StdRng::seed_from_u64(seed ^ b)`) — correct there (every bit pattern is a valid packed payload; this is exactly the realistic-quant data the Q4_K_M bit-identity was established on).
  - v1 scope note: **NaN/Inf/negative-zero edge-value probe fills are a documented follow-up**, not v1 (they need payload-stable comparison semantics; deferred with the annotation-tolerance work).
- **Sizes:** `buffer_sizes: Vec<usize>` (bytes), one per buffer binding, is a **required** request field (its length must equal `meta.binding_plan.buffers.len()`, checked). Rationale: multi-buffer kernels (matmul A/B/C with distinct M·K, K·N, M·N sizes) cannot be inferred from a single scalar. A `--size N` convenience shortcut derives uniform `N`-element buffers **only** for element-wise kernels whose buffers are all the SAME `ScalarTy` and which have `coopmat.is_none()` and `shared_memory_bytes == 0` (saxpy/vector_add class); it ERRORs otherwise (a matmul with three f32 buffers of *different* logical sizes would otherwise silently get equal wrong sizes and a trivial partial-coverage PASS — so `--size` is restricted, not heuristically guessed). Multi-buffer / coopmat / shared kernels must pass explicit `buffer_sizes`.
- **Output sizes:** `output_sizes: Option<Vec<usize>>`, defaults to `buffer_sizes`. Used identically for all dispatches.
- **Push constants (r2/CRIT-1):** `push_constants_base64: Option<String>` (RFC-4648 standard alphabet, decoded via the existing `base64_decode`); must match `meta.push_constant_total_bytes` when present. Same bytes for every dispatch. A `--pc-u32 name=val` / `--pc-f32 name=val` convenience assembles push constants by scalar name from `binding_plan.scalars` (the `assemble_pc` idiom). **The silent all-zero default is FORBIDDEN for any kernel whose `binding_plan.scalars` contains a float (`f32`/`f16`) scalar**: with no push-constants supplied, such a kernel emits verdict `ERROR`, `stage: "preflight"`, `reason.kind: "push_constants_required"`. Justification: saxpy's `alpha:f32` at offset 4 defaults to `0.0`, and `alpha=0` makes `saxpy` compute `y` and `saxpy_perturbed` compute `y` — annihilating the perturbation and turning a REJECT fixture into a false PASS (the exact CRIT-1 hole). Integer-only-scalar kernels may still zero-fill (a benign default). The saxpy-family ATs pin `n = element_count`, `alpha = 2.0` (`0x40000000`) explicitly.
- **Workgroups:** `workgroups: Option<[u32;3]>`; resolved per §3.1 step 5 — mandatory for coopmat/shared kernels (missing ⇒ ERROR), else `derive_workgroups(&buffer_sizes, meta.workgroup_size, None)`. Same grid for every dispatch.

**Non-vacuity meta-guard for reject fixtures (r2/CRIT-1).** A reject fixture is only meaningful if the chosen `(inputs, push-constants)` actually EXERCISE the perturbed path. Every reject-fixture AT must therefore: (a) pin explicit push-constants that make the divergence observable, and (b) assert `n_diff > 0` under `bit-exact` — an assertion that is *itself* the non-vacuity proof (a masked perturbation would yield `n_diff == 0` and fail the test). Additionally, AT-2855 carries an explicit **negative control**: the same pair run with `alpha = 0` is asserted to PASS bit-exact, proving that the default-zero policy WOULD have been vacuous and that the pinned `alpha = 2.0` is load-bearing.

### 3.3 Pass/fail comparison semantics

`TolerancePolicy` (verifier-owned — see §4.2):

| Policy | CLI grammar | Meaning |
|---|---|---|
| `BitExact` (default) | `bit-exact` | `a.to_bits() == b.to_bits()` per element. |
| `Ulp(n)` | `ulp:N` | `within_ulp_f32(a, b, N)` (existing helper, `bench_variant.rs`). |
| `Relative(eps)` | `rel:EPS` | `|a-b| <= eps * max(|a|,|b|, tiny)`, the DESIGN.md §510 relative-tolerance form used by the FROZEN 1e-3 Q4_K_M oracle. |

- Elements are interpreted per the output buffer's element type from `binding_plan` (f32 today; f16 outputs compared as raw 16-bit bit-identity under `BitExact`, or promoted to f32 for `Ulp`/`Relative`). v1 supports f32 and f16 output buffers; other element types fall back to `BitExact` byte-compare with a `notes` annotation.
- **PASS** ⟺ output-buffer set matches in count+size AND every element of every buffer is within policy. **FAIL** otherwise, reporting for each divergent buffer: `n_diff`, `total`, `first_diff_index`, `max_abs_diff`, `max_ulp` (or `max_rel`).
- NaN handling: `within_ulp_f32` already treats NaN≠NaN as a mismatch; documented so a rewrite can't launder NaNs.

### 3.4 Reuse map (no duplication)

| Step | Existing symbol reused | Crate/module |
|---|---|---|
| compile + assignments | `compile_source_with_assignments` | `axc_driver::lib` |
| spirv-val | `mcp::tools::compile_variant::validate_spirv` | `axc-driver` |
| bytes→words | `mcp::tools::compile_variant::bytes_to_words` | `axc-driver` |
| seeded inputs (integer/packed buffers only) | `mcp::tools::bench_variant::seeded_inputs` | `axc-driver` |
| workgroup derive | `mcp::tools::bench_variant::derive_workgroups` | `axc-driver` |
| ULP compare | `mcp::tools::bench_variant::within_ulp_f32` (promote to `pub(crate)`) | `axc-driver` |
| prepare + dispatch | `VulkanContext::prepare_kernel_checked`, `dispatch_handle` | `axc-runtime` |
| metadata / binding plan | `KernelMetadata`, `ParamBindingPlan` | `axc-runtime`, `axc-hir` |

The new code is: the **orchestration** (incl. the determinism self-check dispatch), the **interface diff**, the **element-type-dispatched buffer fill** (well-conditioned float fill + raw-byte reuse for integer/packed — r2/CRIT-3), the **relative-tolerance comparator**, and the **verdict serialization**. Everything touching the GPU/compiler is an existing call.

> **Implementation glue (folded optimistic minors).** `dispatch_handle` takes `workgroups: (u32,u32,u32)` while the request/`derive_workgroups` produce `[u32;3]` — a trivial array→tuple conversion at the call site. `dispatch_handle` takes `inputs: &[&[u8]]` while the fills produce `Vec<Vec<u8>>` — an `.iter().map(|v| v.as_slice()).collect()` step. Both are noted so the ~450-LOC core estimate carries the headroom.

## 4. Anti-reward-hacking gates

A rewrite is a hostile input (the LLM may reward-hack). The gates:

### 4.1 Interface immutability (the primary structural gate)

`diff_interface(orig, rewritten)` rejects unless the two `KernelMetadata` describe the **same observable interface**:

- **Buffer bindings:** same count; for each position, same `name`, same element `ScalarTy`, same `BufferAccess`, same `buffer_position`. A rewrite cannot add/drop/reorder/retype/re-access a buffer. `BufferAccess` has **three** variants — `ReadOnly` / `ReadWrite` / `WriteOnly` (`axc-hir/src/buffer.rs`) — and all three are compared for equality, so an output-aliasing cheat (`WriteOnly → ReadWrite`, or `ReadOnly → ReadWrite`) is caught (r2, folded from review).
- **Scalar push-constants:** same count; for each, same `name`, same `ScalarTy`, same `offset`, same `member_index`; same `push_constant_total_bytes`.
- **Workgroup size:** `meta.workgroup_size` must match (dispatch geometry + output tiling depend on it; required so the two runs are comparable with a single derived grid).
- **NOT gated:** `kernel_name` / `entry_point` (a rewrite legitimately renames — e.g. the real historical pair `q4km_..._cached` → `q4km_..._cached_sr`), `coopmat` shape, `shared_memory_bytes`, SPIR-V capabilities, body structure. These are *internal implementation*, which is exactly what a structural rewrite is allowed to change.

This gate is a pure function of two `KernelMetadata` values → fully CPU-testable, and it fires before GPU dispatch so a signature cheat costs no GPU.

### 4.2 Tolerance is owned by the verifier, not the kernel — and *governed* on the request path (r2/CRIT-2)

The comparison tolerance is **never read from the kernel source**. This structurally defeats the **source-annotation** weakening attack: the rewritten kernel has **no channel** to loosen the bar it is judged against (there is no HIR path from `@equiv_fp_tol` to the comparator — §4.3). That guarantee is real and complete *for the kernel source*.

**Honest scope — the request-level knob is governed, not eliminated.** Tolerance is also a *request* input (`tolerance`, default `BitExact`). On the **CLI/CI path** the setter is a non-agent operator, so it is a plain, audit-visible operator choice (echoed as `policy` in the verdict). On the **MCP path the caller IS the agent** (Claude, in this pipeline's self-optimize loop) — the same LLM that proposes the rewrite could also pick the tolerance it is judged under. Left unguarded, that is a front door on the very path the thesis targets. Two mitigations make the loosening impossible to do **silently**:

1. **Server-owned default.** The MCP tool's default policy is `BitExact` (server-set), not caller-set. A caller must *actively* pass a looser tolerance.
2. **Loud override stamp.** Any MCP-supplied tolerance looser than the server default is accepted **only** with `tolerance_overridden: true` at top level and a `notes` entry `"tolerance_loosened_by_caller: <policy>"` in the verdict. **Decision: accept-with-loud-stamp rather than hard-reject**, justified because the verdict consumer is the **outer supervisor agent**, which CAN and does audit the verdict JSON (pipeline rule #3 — verdict is machine-parsed and gated on); a loosened bar therefore cannot reach a merge decision without the supervisor seeing the stamp. (A hard-reject floor is a legitimate stricter alternative, deferred as a config knob.) The CLI path is un-stamped: the operator there owns the policy directly.

So: the source-annotation attack is *structurally defeated*; the request-level knob is *governed* (server default + non-silent, audit-forced override), **not eliminated**. AT-2855 demonstrates the source side: a ~1-ULP-perturbed rewrite FAILs under default `bit-exact` and PASSes only under an explicit `rel:1e-3`. AT-2860 demonstrates the governance: an MCP `rel:1e-3` call carries `tolerance_overridden: true`.

### 4.3 Why `@equiv_fp_tol` is not read from source in v1 (scope + honesty)

`@equiv_fp_tol` appears in DESIGN.md as the intended tolerance annotation, but **it is not currently parsed into HIR** (grep: no `EquivFpTol` in `axc-hir`; the FROZEN 1e-3 lives in test code, and `axc-optimize::CorrectnessPolicy::EquivFpTol{ulp}` is a ULP policy set by the `axc optimize --correctness` flag, not sourced from the kernel). Reading it from source would require a new HIR annotation-lowering feature = a compiler change, which this milestone explicitly forbids. Therefore v1 takes the tolerance as an explicit policy argument (reusing the exact `none|bit-exact|fp-tol` grammar family already on `axc optimize`). **Non-goal:** annotation-sourced tolerance; it becomes a clean follow-up once `@equiv_fp_tol` is a real HIR annotation (a separate FG-class feature). This is the honest, smaller v1.

### 4.4 Other gates (fall out of the design)

- **Same seeded inputs to both** — a rewrite cannot request friendlier data.
- **Output-size parity** — the two runs must produce the same output-buffer shape.
- **spirv-val on both** — a rewrite cannot ship malformed SPIR-V that a driver might "optimize" into passing.
- **Determinism** — fixed seed + fixed grid fix the INPUT bytes, making a *given* dispatch reproducible. It does NOT by itself make the *kernel* deterministic (atomics / unordered subgroup ops / uninitialized shared reads vary run-to-run). The **determinism self-check** (§3.1 step 7 — original dispatched twice, self-disagreement ⇒ `NONDETERMINISTIC_ORACLE`) is what protects the verdict from a nondeterministic oracle; without it, "reproducible verdict" would be an overclaim for such kernels (r2/WARN-2).

### 4.5 Benchmark comparison is OUT of scope for v1 — justification

v1 is **correctness-verify-only**. Reasons: (a) FG.1's stated scope is "correctness verification harness that compares rewritten kernel output to original" — the anti-reward-hacking correctness gate is the value; (b) M3.13 closed the perf campaign, so a speed verdict is not this milestone's point; (c) timing already exists — `bench_variant` and `grid_search` (M2.4) plus the resident benches produce measured numbers, so folding perf into `rewrite-verify` would duplicate that machinery and risk conflating a *correctness* verdict with a *speed* claim (precisely the reward-hacking surface we are hardening). A future `--bench` flag can add an optional timing comparison that reuses the resident-bench path and reports a *separate* `speedup` field without gating the correctness verdict. **Non-goal for M3.16.**

## 5. Verdict JSON schema

`"verdict"` is the FIRST key (pipeline enforcement rule #3). Emitted to stdout by the CLI and returned as the MCP `result`.

**Closed verdict set (r2/WARN-3):** `PASS | FAIL | REJECT | SKIPPED | NONDETERMINISTIC_ORACLE | ERROR`. No other value is emitted; the enum is exhaustive.

```jsonc
{
  "verdict": "PASS",                 // one of the 6 above
  "milestone": "M3.16",
  "policy": "bit-exact",             // echoes the tolerance policy used (audit trail)
  "tolerance_overridden": false,     // true iff an MCP caller loosened past the server default (§4.2)
  "seed": 0,
  "stage": "output",                 // producing stage (closed set):
                                     //   compile | spirv_val | interface | preflight
                                     //   | self_check | dispatch | output
  "original":  { "kernel_name": "q4km_..._cached",    "buffers": 5, "scalars": 3, "workgroup": [128,1,1] },
  "rewritten": { "kernel_name": "q4km_..._cached_sr", "buffers": 5, "scalars": 3, "workgroup": [128,1,1] },
  "device": "NVIDIA RTX PRO 6000 ...", // present when dispatched; null on CPU-only verdicts
  "buffers_compared": [
    { "index": 3, "size_bytes": 4194304, "elem": "f32", "n_diff": 0, "total": 1048576,
      "max_abs_diff": 0.0, "max_ulp": 0, "max_rel": 0.0 }
  ],
  "reason": null,                    // populated for every non-PASS verdict (closed `kind` set below)
  "notes": []                        // e.g. "tolerance_loosened_by_caller: rel:0.001"
}
```

**Closed `reason.kind` set** (exhaustive; every non-PASS verdict carries exactly one):

| Verdict | `stage` | `reason.kind` | Notes |
|---|---|---|---|
| `FAIL` | `compile` | `compile_fail_original` / `compile_fail_rewritten` | `+ lex/parse/hir counts, detail, side` |
| `FAIL` | `spirv_val` | `val_fail_original` / `val_fail_rewritten` | `+ validator detail, side` |
| `REJECT` | `interface` | `interface_mismatch` | `+ InterfaceMismatch sub-kind` (below) |
| `ERROR` | `preflight` | `workgroups_required` / `push_constants_required` | request under-specified for a coopmat/shared/float-scalar kernel |
| `FAIL` | `preflight` | `preflight_fail_rewritten` | rewritten `prepare/dispatch` `DispatchError` (e.g. shared over `maxComputeSharedMemorySize`) — an unrunnable rewrite fails |
| `SKIPPED` | `preflight`/`dispatch` | `preflight_fail_original` | original hit device incapacity (not a candidate verdict) |
| `NONDETERMINISTIC_ORACLE` | `self_check` | `original_nondeterministic` | `+ disagreeing buffer stats` (§3.1 step 7) |
| `SKIPPED` | `dispatch` | `gpu_unavailable` / `coopmat_unsupported` / `device_feature_unsupported` | typed-skip |
| `FAIL` | `output` | `numeric_mismatch` | `+ buffers_failed, worst{index,n_diff,max_rel}` |
| `ERROR` | `preflight`/`dispatch` | `infra_error` | internal/IO/decode failure on either side; never a panic |

`InterfaceMismatch` sub-kinds (inside the `interface_mismatch` reason): `buffer_count`, `buffer_name`, `buffer_type`, `buffer_access`, `scalar_mismatch`, `push_constant_bytes`, `workgroup_size`. Example: `{ "kind": "interface_mismatch", "sub": "buffer_access", "detail": "buffer[2] access differs: original=ReadOnly rewritten=ReadWrite" }`.

**CLI exit codes:** `PASS`/`SKIPPED`/`NONDETERMINISTIC_ORACLE` → 0 (the last is a clean "no verdict renderable", not a candidate failure); `FAIL`/`REJECT` → 1; `ERROR` (usage / under-specified request / I/O) → 2. The verdict JSON is always written to stdout regardless of exit code (so CI can parse it).

```rust
    #[serde(default)] pub seed: u64,
}
// Response is the VerifyReport (serde::Serialize) from §6.1.
pub(crate) fn handle(req: VerifyRewriteRequest, ctx: &mut McpContext)
    -> Result<crate::rewrite_verify::VerifyReport, McpToolError>;
```

Resolves each source via the existing `resolve_source(&src, &path)` exactly-one-of rule, decodes push constants via existing `base64_decode`, obtains `ctx.vulkan.get_or_init()` — **Vulkan-unavailable here is an RPC error `VULKAN_UNAVAILABLE (-32004)`** (the caller asked to verify and we could not), whereas the CLI's local `.ok()` produces a `SKIPPED` verdict for CI ergonomics. (Documented divergence: MCP callers want a hard error; CI wants a skip.) A compile/spirv-val/interface/output outcome is a normal `Ok(report)` with the verdict inside — those are verification results, not protocol errors.

**Server-owned tolerance policy (r2/CRIT-2).** The MCP `tolerance` field defaults to the **server-set** `BitExact` (via `default_bit_exact`), never a caller default. Before running, the handler compares the caller's parsed policy against the server default: if it is **looser** (any non-`BitExact`), the handler sets `report.tolerance_overridden = true` and pushes `notes += "tolerance_loosened_by_caller: <policy>"`. This is `accept-with-loud-stamp` (not hard-reject): the verdict is consumed by the outer supervisor agent (pipeline rule #3, machine-parsed and merge-gating), so the stamp is guaranteed-audited and a silent loosening on the agent-driven path is impossible. The CLI path leaves `tolerance_overridden = false` (the operator owns the policy directly).

## 9. Non-goals (explicit scope fence)

1. **No `propose_rewrite` / in-compiler LLM call.** Generation stays in the agent. (§2)
2. **No prompting infrastructure / iteration loop.** The agent loops by calling `verify_rewrite` repeatedly; that orchestration is not compiler code.
3. **No `@equiv_fp_tol`-from-source.** Tolerance is an explicit verifier input; annotation-sourced tolerance waits on a real HIR annotation feature (compiler change). (§4.3)
4. **No benchmark/perf verdict.** Correctness-only v1; timing lives in `bench_variant`/`grid_search`. Optional `--bench` is a future add. (§4.5)
5. **No workgroup-size-changing rewrites.** v1 requires `workgroup_size` parity so a single derived grid compares both. Geometry-changing rewrites are a follow-up.
6. **No multi-kernel-module diffing.** v1 verifies the first (only) kernel per module, consistent with the rest of the pipeline.
7. **No auto-sizing for arbitrary kernels.** `buffer_sizes` is explicit (with a `--size` shortcut for same-`ScalarTy` element-wise kernels only; coopmat/shared/multi-size kernels must pass explicit sizes). (§3.2)
8. **No verdict for nondeterministic-oracle kernels.** A nondeterministic original is *detected* (`NONDETERMINISTIC_ORACLE`, §3.1 step 7) but no PASS/FAIL is rendered for the candidate; deterministic-repair is out of scope. (§10)
9. **No edge-value input probes.** v1 uses well-conditioned finite fills; NaN/Inf/negative-zero probe fills (with payload-stable comparison) are a documented follow-up alongside the annotation-tolerance work. (§3.2/CRIT-3)
10. **Request-tolerance is governed, not eliminated.** The MCP path allows a caller-loosened tolerance but forces a loud, supervisor-audited `tolerance_overridden` stamp; a hard-reject floor is a deferred config knob. (§4.2)

## 10. Correctness oracle statement

The oracle **is** the original kernel: the check is A-vs-B differential equivalence under a verifier-owned tolerance (`BitExact` default, `Ulp{n}`, or `Relative{eps}` matching the DESIGN.md §510 relative form). No CPU reference is authored — this is what lets the harness generalize to any kernel without per-kernel oracle registration. Equivalence is asserted on real-GPU outputs (Lavapipe CI fallback), never mocked.

**Two documented intrinsic limitations (oracle honesty, r2):**
1. **Shared-oracle-bug blindness.** Because equivalence is *relative to the original*, a rewrite that triggers the SAME driver/hardware bug as the original passes undetected — differential testing verifies "same behavior as original," not "same behavior as the mathematical spec." This is inherent to A-vs-B (Csmith/Alive2 share it) and is not fixable within this milestone; a CPU-reference oracle (per-kernel, non-generalizing) would be the orthogonal complement.
2. **Deterministic-oracle assumption.** The verdict is meaningful only when the original is deterministic. The determinism self-check (§3.1 step 7) *detects* a nondeterministic original and emits `NONDETERMINISTIC_ORACLE` rather than a false verdict against the candidate, but it cannot *repair* one — nondeterministic kernels are outside the set this harness can render a PASS/FAIL for.
