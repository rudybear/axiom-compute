## 0. Current-state findings (verified in-tree, both halves)

These corrections to the ROADMAP framing are load-bearing for the decisions:

1. **Neither annotation is "currently parsed but no semantics" (ROADMAP FG.2 wording is inaccurate).**
   Annotation *names* lex as a generic `TokenKind::Annotation(String)` and the *arg list* parses,
   but HIR lowering (`crates/axc-hir/src/lower.rs:55-186`) has a **closed whitelist**; any name
   not in `{kernel, workgroup, intent, complexity, precondition, postcondition, subgroup_uniform,
   cooperative_matrix, strict, strategy}` hits the `other =>` arm and is **REJECTED** with
   `HirError::UnknownAnnotationInM0` (`crates/axc-hir/src/validate.rs:61`). So today a kernel that
   carries `@transfer { … }` or `@optimization_log { … }` **fails to compile**. Accepting either
   name is therefore a real (if one-line) HIR change, not a no-op.

2. **DESIGN.md §3.2 does NOT list `@transfer` or `@optimization_log`.** The §3.2 annotation table
   (DESIGN.md:1457-1479) lists neither. They exist only as ROADMAP feature-gap stubs (FG.2/FG.3).
   This milestone adds them to §3.2.

3. **The external optimization history (M2.4) works but orphans under rewrite.** `grid_search`
   appends `HistoryEntryRecord` JSONL via `append_history_entry` (flock-serialized) to
   `.pipeline/history/<xxh3_hex16(source)>.jsonl`; `optimization_history` reads it back
   (`crates/axc-driver/src/mcp/tools/{grid_search,optimization_history}.rs`). The path key is
   `xxh3_64(source_bytes)` (`history_path_for_source`) — **any source edit changes the key**, so
   the history of a kernel is unfindable the moment an agent rewrites it. `.pipeline/history/`
   currently holds only `.gitkeep` (no accumulated runs), consistent with "the content-hash channel
   is not surviving the workflow." **This is the concrete, falsifiable weakness FG.3 addresses.**

4. **No consumer reads `@transfer`.** The MCP dispatcher (`crates/axc-driver/src/mcp/dispatch.rs`)
   exposes exactly 7 tools — `load_source, compile_variant, bench_variant, grid_search,
   enumerate_variants, optimization_history, verify_rewrite` — none of which reads an in-source
   handoff block. The 7-agent supervisor routes work via external `.pipeline/runs/M*-<agent>.json`
   verdict files (this very file's sibling). **There is nothing in-repo that a `@transfer` block
   would feed.**

### 0.5 The cheap alternative, weighed honestly (should-fix, both reviewers)

Both reviewers asked why we embed rather than take the ~50-LOC fix of **re-keying the external
JSONL by a stable kernel identity** (e.g. `history_dir.join(kernel_name)` or a content-independent
`stable_id`) instead of `xxh3_64(source_bytes)`. The honest weighing: **embedding wins on three
axes the rekey cannot cover, and the rekey is a complementary future fix, not a substitute.**

- **Survives file moves/renames.** A kernel-name/stable-id key in `.pipeline/history/` still lives
  in a side directory addressed relative to repo layout; moving or renaming the `.axc` (or vendoring
  it into another tree) orphans the side-channel again. The embedded block travels *inside the
  source bytes* — it cannot be separated from the kernel it describes.
- **Zero side-channel dependency.** Any agent that can read the `.axc` sees the history with no
  second lookup, no `.pipeline/history/` mount, no path convention to agree on. This is the on-thesis
  property: the source is self-describing.
- **Visible to any reader.** An LLM (or human) opening the file in review sees prior verdicts inline;
  the rekey leaves the history in a machine-only JSONL an agent must know to fetch.

**But the rekey is genuinely cheaper and still worth doing later — as a complement.** The external
JSONL remains the machine-run *archive* (full bench detail, flock-serialized, unbounded). Re-keying
it by stable identity would stop the archive itself from orphaning and is orthogonal to embedding.
So: **build FG.3 now (rewrite-surviving inline summary, bounded at 64 entries); file the JSONL rekey
as a separate small future fix.** We are not asserting embedding is strictly better on every axis —
it costs source bytes and merge noise (§5); we are asserting it is the only channel that satisfies
the *survives-rewrite-and-move, self-describing* requirement that motivated the milestone.

## 1. FG.3 — `@optimization_log { … }` — MINIMAL-BUILD spec

### 1.1 Scope (what ships)

- **Read + validate + round-trip** a first-class structured block (anti-pattern #7: typed fields,
  not a string blob).
- **ONE writer**: a new LLM-free `axc log-opt` CLI primitive (+ a thin `append_optimization_log`
  MCP wrapper, mirroring the M3.16 CLI-primitive-plus-MCP-tool pattern) that appends a structured
  entry to a source file's block, creating the block if absent, with byte-stable formatting.
- **Codegen-inert**: the block reaches HIR but is **never** handed to codegen; SPIR-V is
  byte-identical with and without it (golden-gated, mirroring M3.17's `--debug`-off gate).

### 1.2 Grammar changes (flagged precisely)

| Layer | Change | Detail |
|---|---|---|
| **Lexer** | **NONE** | `@optimization_log` already lexes as `TokenKind::Annotation("optimization_log")`. |
| **Parser** | **new block arm** | In `parse_annotations` (`parser.rs:331-348`), add a special-case sibling to the `strategy` arm: when `name_str == "optimization_log" && peek == LBrace`, call a new `parse_optimization_log_block`. This is **NOT** a true mirror of `parse_strategy_block` (whose value grammar is `?[…]`-only); it uses its own **closed, non-recursive** value grammar (§1.3a). Graceful recovery: report all malformed-entry errors, re-sync at the next `entry` / `,` / `}`, do not abort the file. |
| **AST** | **new arg carrier + CLOSED value type** | Add `AnnotationArg::Record { fields: Vec<Spanned<RecordField>> }` where `pub struct RecordField { pub key: Spanned<String>, pub value: Spanned<RecordValue> }`. **`RecordField.value` is a NEW closed `RecordValue` enum — NOT `Spanned<AnnotationArg>`** (that recursive type would admit nested records, `Call`, `Hole`/`HoleRef`; see §1.3a). `pub enum RecordValue { Str(String), Int(i64), Ident(String) }` — exactly three scalar shapes, no recursion. Each `entry { … }` lowers to one `Record` wrapped in `Call { name: "entry", args: [Record] }` so downstream match arms stay uniform; block-level scalars (`version`) are `RecordField`s directly under the block `Record`. **Structured records with float-free metrics without touching the `Int`-only literal grammar** (metrics are integer + a unit ident carrying scale; see §1.4). |
| **HIR** | **new whitelist arm + validation** | In `lower.rs` add `"optimization_log" => { … }` before the `other =>` reject arm; validate the block against the fixed schema (§1.4) and store `OptimizationLog` (version + `Vec<OptimizationLogEntry>`) on the kernel HIR. New module `crates/axc-hir/src/opt_log.rs` holds the structs + validator + `MAX_OPT_LOG_ENTRIES` cap + `SUPPORTED_OPT_LOG_VERSION`. Duplicate `@optimization_log` on one kernel → `HirError::DuplicateAnnotation` (mirror `workgroup`, `lower.rs:66-74`). Empty block (version only, zero entries) → `HirWarning::EmptyOptimizationLog` (mirror `EmptyStrategyBlock`). New error `HirError::BadOptimizationLogEntry { detail, span }`; new block-level error `HirError::BadOptimizationLog { detail, span }` (missing/invalid `version`). New forward-compat warning `HirWarning::UnknownOptimizationLogKeyForward { version, key, span }` (§1.4a). |
| **Codegen** | **NONE** | The entries live on HIR only; the codegen entry path never reads them. Golden-gated at AT-2903. |

No new SPIR-V capability or extension (anti-pattern #7 / architect rule 39: nothing silent — the
block emits nothing at all).

### 1.3 Block grammar (concrete)

```
@optimization_log {
  version: 1,                                       // REQUIRED, block-level, exactly once (§1.4a)
  entry {
    ts:      "2026-07-14T12:00:00.000Z",            // string (RFC3339 shape)
    kernel:  "q4km_matmul_rb_coopmat_f32acc_cached", // string
    metric:  42860,                                 // i64 (scale carried by `unit`, §1.4)
    unit:    mtflops,                               // ident, closed set (§1.4)
    verdict: PASS,                                  // ident, closed set (§1.4)
    note:    "M3.6 leader; 2.39x behind llama"      // optional string
  },
  entry { ts: "…", kernel: "…", metric: 41640, unit: mtflops, verdict: REGRESS }
}
```

- Field order within an entry is free; required fields enforced by the validator.
- Trailing commas permitted at **both** levels (after the last `entry` and after the last field
  inside an `entry`), matching `parse_strategy_block` tolerance but explicitly two-level.
- `verdict` and `unit` are **idents from a closed set** (not free strings), so they are first-class
  data, not stringly-typed (anti-pattern #7). See §1.4 for the frozen vocabularies.

### 1.3a Formal production (CLOSED — the grammar-forever pin)

```ebnf
opt_log_block   := "{" block_item ("," block_item)* ","? "}"
block_item      := version_field | entry_block
version_field   := "version" ":" int_lit          (* int_lit here MUST be a non-negative integer *)
entry_block     := "entry" "{" field ("," field)* ","? "}"
field           := ident ":" record_value
record_value    := string_lit | int_lit | ident    (* NO record, NO call, NO hole/holeref *)
int_lit         := ["-"] DIGIT+                     (* sign accepted by the LEXER/parser;
                                                       per-field sign legality decided in §1.4 *)
```

Hard rules the production enforces (all become reject fixtures / ATs):

- **`entry` and `version` are contextual hard keywords** *inside* the `@optimization_log` block
  only (they remain ordinary identifiers elsewhere). A typo `netry { … }` or `versoin: 1` →
  parse error "expected `entry` or `version`", recover at the next `,` / `}`.
- **`record_value` is closed to three scalar shapes** (`string_lit | int_lit | ident`). The parser
  itself rejects — with recovery — any of: a nested record (`k: { … }`), a call (`k: f(3)`),
  a hole or hole-ref (`k: ?x`, `k: ?[a,b]`). These can never reach the validator because
  `RecordValue` (§1.2) has no variant to hold them.
- **Nesting is structurally impossible**: `entry` may not contain `entry` (no `Record` variant in
  `RecordValue`), so `entry { entry { … } }` is a parse error, not deep recursion.
- **Sign at the token level, legality at the schema level**: the parser accepts a leading `-` on an
  integer so it can produce a well-formed `RecordValue::Int(-5)` and hand the validator a precise
  span; whether a negative value is *legal* is decided per unit in §1.4 (a negative `mtflops`/`ns`/
  `us`/`ms`/`bytes` is rejected as nonsensical; a negative `pct_milli` delta is legal).

### 1.4 Schema (`opt_log.rs`)

```rust
pub const MAX_OPT_LOG_ENTRIES: usize = 64;      // bounds source growth / merge noise
pub const SUPPORTED_OPT_LOG_VERSION: i64 = 1;   // this compiler's schema version

pub struct OptimizationLog {
    pub version: i64,                        // required block field; == 1 for this compiler (§1.4a)
    pub entries: Vec<OptimizationLogEntry>,  // 0..=MAX_OPT_LOG_ENTRIES
    /// Block-level keys unknown to this compiler, preserved verbatim ONLY when version > SUPPORTED
    /// (forward-compat, §1.4a). Always empty for a version==1 block (unknown key → reject there).
    pub forward_unknown: Vec<(String, RecordValue)>,
}

pub struct OptimizationLogEntry {
    pub ts: String,               // required; non-empty; RFC3339 shape-validated only
    pub kernel: String,           // required; non-empty
    pub metric: i64,              // required; sign legality is unit-dependent (§1.4, table below)
    pub unit: OptLogUnit,         // required; closed enum
    pub verdict: OptLogVerdict,   // required; closed enum
    pub note: Option<String>,     // optional
    /// Entry-level unknown keys, preserved verbatim ONLY when version > SUPPORTED (§1.4a).
    pub forward_unknown: Vec<(String, RecordValue)>,
}

pub enum OptLogUnit { MilliTflops, MilliPercent, Nanoseconds, Microseconds, Milliseconds, Bytes }
pub enum OptLogVerdict { Pass, Fail, Reject, Skipped, NondeterministicOracle, Error, Regress }

pub fn validate_block(block_fields: &[RecordField], span: Span) -> Result<OptimizationLog, HirError>;
pub fn validate_entry(fields: &[RecordField], version: i64, span: Span)
    -> Result<OptimizationLogEntry, HirError>;
```

**Frozen `unit` vocabulary (closed ident set — the scale is carried BY the unit name, self-evident):**

| ident      | enum variant   | meaning                       | scaling            | sign rule            |
|------------|----------------|-------------------------------|--------------------|----------------------|
| `mtflops`  | `MilliTflops`  | throughput, milli-TFLOPS      | TFLOPS × 1000      | `metric ≥ 0` (reject `<0`) |
| `pct_milli`| `MilliPercent` | percentage, milli-percent     | % × 1000           | **signed** (deltas allowed) |
| `ns`       | `Nanoseconds`  | latency, nanoseconds          | raw (no scaling)   | `metric ≥ 0` (reject `<0`) |
| `us`       | `Microseconds` | latency, microseconds         | raw                | `metric ≥ 0` (reject `<0`) |
| `ms`       | `Milliseconds` | latency, milliseconds         | raw                | `metric ≥ 0` (reject `<0`) |
| `bytes`    | `Bytes`        | size/bandwidth counter, bytes | raw                | `metric ≥ 0` (reject `<0`) |

This settles the optimistic reviewer's `metric_milli` inconsistency: **the `_milli` scaling lives in
the unit name, not the field name.** `mtflops`/`pct_milli` are ×1000 fixed-point (they carry
sub-integer precision, e.g. 42.86 TFLOPS → `metric: 42860, unit: mtflops`); `ns`/`us`/`ms`/`bytes`
are raw integers (already integer-precise at that unit — no wasted milli digits, no per-unit
redefinition of "milli"). The field is named `metric` (unit-neutral), never `metric_milli`.

**Frozen `verdict` vocabulary (closed ident set):** the six `rewrite_verify::Verdict` variants
**verbatim** in their SCREAMING_SNAKE_CASE serialized form (verified at `rewrite_verify.rs:151-157`
— `#[serde(rename_all = "SCREAMING_SNAKE_CASE")]`), plus grid-search's `REGRESS`:

```
{ PASS, FAIL, REJECT, SKIPPED, NONDETERMINISTIC_ORACLE, ERROR, REGRESS }
```

Note the ident is `NONDETERMINISTIC_ORACLE` (matching the real `NondeterministicOracle` variant),
**not** the r1 `NONDETERMINISTIC`; and there is **no `Regress`** in `rewrite_verify` — `REGRESS`
originates only from grid-search (see the mapping table in §1.5). No M3.17/M3.18 verdict additions
exist (verified: `Verdict` is unchanged since M3.16).

`validate_entry`/`validate_block` reject (all `HirError::BadOptimizationLogEntry` /
`HirError::BadOptimizationLog` with precise `detail` + span; parser recovers so *all* bad items are
reported, anti-pattern #6): missing required field, duplicate key within an entry, wrong
`RecordValue` shape for a field (e.g. `Str` where `Int` required), out-of-set `unit`/`verdict`
ident, negative `metric` under a `≥0` unit, missing/duplicate/negative/non-`Int` `version`,
`> MAX_OPT_LOG_ENTRIES` entries, and — for **version == SUPPORTED** — any unknown key (typo
protection). For **version > SUPPORTED**, unknown keys are preserved-and-warned instead (§1.4a).

### 1.4a `version` + forward-compatibility rule (the exact, both-directions pin)

`version: <int>` is **required, block-level, exactly once**. `SUPPORTED_OPT_LOG_VERSION = 1`.

| condition | behavior |
|---|---|
| `version` absent, duplicated, non-`Int`, `< 1` | **REJECT** `HirError::BadOptimizationLog` |
| `version == 1` (== SUPPORTED), **unknown** block/entry key | **REJECT** `BadOptimizationLog`/`BadOptimizationLogEntry` — *typo protection* (a v1 block is fully known; an unrecognized key is a mistake) |
| `version == 1`, all keys known | validate against the v1 schema as usual |
| `version > 1` (> SUPPORTED, a future writer), **unknown** key | **PRESERVE-AND-WARN**: stash into `forward_unknown`, emit `HirWarning::UnknownOptimizationLogKeyForward { version, key, span }`; do **not** reject — *forward-compat* (an old compiler must not hard-fail on a newer, additively-extended block) |
| `version > 1`, **known** required fields | still validated (present + well-typed + in-set); a future version that *changes an existing field's value-set or type* is a breaking change out of v1's forward-compat scope — v1 still validates the known field by v1 rules and will reject an out-of-v1-range value. Forward-compat covers **additive new keys only.** |

Both directions carry ATs: version==1 + unknown key → reject (AT-2923); version==2 + unknown key →
preserve-and-warn, entry otherwise accepted (AT-2924). `forward_unknown` also lets the writer's
byte-verbatim round-trip (AT-2904/2925) carry future keys through untouched.

**Rotation is deferred** (see §1.5 writer cap + §1.8): at 64 entries the writer fails closed; we do
not evict-oldest in the minimal build.

### 1.5 Writer — `axc log-opt` (the ONE integration; the falsifiable value proof)

```
axc log-opt <source.axc>
    --kernel <name> --metric <i64> --unit <mtflops|pct_milli|ns|us|ms|bytes>
    --verdict <PASS|FAIL|REJECT|SKIPPED|NONDETERMINISTIC_ORACLE|ERROR|REGRESS>
    [--ts <rfc3339>]        # default: wall-clock now() UTC ms — NON-REPRODUCIBLE (see below)
    [--note <string>]
  # or ingest a prior run instead of raw flags:
    [--from-verify <VerifyReport.json>]     # maps rewrite_verify verdict+metric → an entry
    [--from-grid  <HistoryEntryRecord.json>] # maps grid_search winner → an entry
```

- Signature: `crates/axc-driver/src/log_opt.rs` —
  `pub fn append_optimization_log(source_path: &Path, entry: OptimizationLogEntry) -> Result<(), LogOptError>`
  plus `entry_from_verify_report(&VerifyReport) -> OptimizationLogEntry` and
  `entry_from_grid_record(&HistoryEntryRecord) -> OptimizationLogEntry`.
- **Mechanism (source-preserving splice, not reformat):** read the source; parse; if an
  `@optimization_log` annotation exists, locate its block byte-span (annotations carry a `span`,
  `Spanned<Annotation>`) and splice the new `entry { … }` before the closing `}`, preserving any
  block-level `version` / future keys; if absent, insert a fresh
  `@optimization_log { version: 1, entry { … } }` immediately **before** the first leading annotation
  of the (single) kernel. Everything outside the spliced region is preserved **byte-for-byte**
  (AT-2906). Deterministic, stable indentation. LLM-free, no GPU → CI-runnable.
- **Fail-closed at capacity (never emit an uncompilable file):** before splicing, the writer counts
  existing entries; if the block is already at `MAX_OPT_LOG_ENTRIES` (64), it **refuses** with a
  distinct machine-readable, exit-coded `LogOptError::Full { current: 64, max: 64 }` and leaves the
  source **byte-for-byte unchanged** — it never writes the 65th entry that would then fail
  `axc compile`/`rewrite-verify`/`test` with `BadOptimizationLog`. (Rotation/evict-oldest is
  **deferred**, §1.8; the minimal build fails closed.) AT-2922.
- **Single-kernel only (fail-closed):** a source with two or more `@kernel` items → the writer
  refuses with `LogOptError::Multikernel` and does not write (which of several kernels owns the block
  is FG.9 territory, not built). One block per single-kernel file; stated here, not only in JSON.
- **`--ts` reproducibility:** the default `now()` is **non-reproducible** and is fine for production
  agent/CLI use, but is **banned in ATs** — every golden/round-trip fixture (AT-2903/2904/2905/2906/
  2912/2925) **must** pass an explicit `--ts`. The MCP wrapper inherits the same rule: reproducible
  callers pass an explicit `ts`; the wrapper must not silently inject `now()` for such callers.
- **`--from-verify` / `--from-grid` verdict mapping (exhaustive, tested at AT-2907):**
  `entry_from_verify_report` maps **all six** `rewrite_verify::Verdict` variants 1:1 to the
  identically-named `OptLogVerdict`; `REGRESS` is **never** produced here (it has no `rewrite_verify`
  source) — it is emitted only by `entry_from_grid_record` when the grid winner regresses versus the
  recorded baseline.

  | source | `rewrite_verify::Verdict` | → `OptLogVerdict` ident |
  |---|---|---|
  | verify | `Pass` | `PASS` |
  | verify | `Fail` | `FAIL` |
  | verify | `Reject` | `REJECT` |
  | verify | `Skipped` | `SKIPPED` |
  | verify | `NondeterministicOracle` | `NONDETERMINISTIC_ORACLE` |
  | verify | `Error` | `ERROR` |
  | grid   | (winner regressed vs baseline) | `REGRESS` |

- **Concurrency:** whole-file rewrite (last-writer-wins). Unlike the JSONL `append_history_entry`
  flock path, no advisory lock; document "do not run `log-opt` concurrently on the same file"
  (loud stderr note; a `--force`/lock is deferred).
- **MCP wrapper:** `append_optimization_log` tool (`crates/axc-driver/src/mcp/tools/
  append_optimization_log.rs`) is a thin server-side call into `log_opt::append_optimization_log`
  so the agent loop's on-thesis consumer (the MCP server) can write self-describing history without
  a shell. Registered as the 8th method in `dispatch.rs`.

### 1.6 Reader (minimal)

For the minimal build the "reader" is: the block round-trips through the whole toolchain
**unchanged and error-free** — `axc lex`, `axc compile` (byte-identical SPIR-V), HIR, and
`rewrite-verify`/`verify`/`test` all accept a source carrying the block. Agents reading the `.axc`
source see prior attempts inline. **Deferred (not built):** extending `optimization_history` to
*merge* embedded-block entries with the external JSONL, and any authority/dedup policy between the
two channels (see §1.8).

### 1.7 Correctness oracle

Not a perf milestone → no FP oracle. The oracle is **byte-identical SPIR-V**: AT-2903 compiles a
kernel with and without the `@optimization_log` block and asserts the two `.spv` outputs are
byte-for-byte equal (annotations must not perturb codegen). Same discipline as M3.17's `--debug`-off
golden gate and M3.9/M3.10a "empty codegen diff" gates.

### 1.8 Deferred (FG.3)

- Second/third writers (grid_search / rewrite-verify auto-appending on every run) — ONE writer for
  minimal; auto-write is source churn we do not commit to yet.
- Deprecating or unifying the external JSONL; the merged reader; dedup/authority policy.
- Multi-kernel modules (FG.9 not built) — one block per (single) kernel/file; the writer fails
  closed (`LogOptError::Multikernel`) on a two-kernel source.
- **Entry rotation / evict-oldest** — the minimal writer **fails closed** at `MAX_OPT_LOG_ENTRIES`
  (`LogOptError::Full`); a rotation policy (keep-newest-N, or summarize-and-drop) is deferred.
- The JSONL **rekey by stable identity** (§0.5) — a complementary future fix to the machine archive,
  independent of and not superseded by embedding.
- Float-literal annotation args — sidestepped via integer + unit ident carrying scale.

## 2. FG.2 — `@transfer { … }` — NO-BUILD (paper finding)

### 2.1 Decision

**NO-BUILD.** Ships as a spec + verdict + AT-numbered analysis (AT-2915..2918), in the class of
M3.10b (specified-but-not-taken) and M3.13 PRONG B (blocked/paper-finding). **No parser, AST, HIR,
or codegen change for `@transfer`.** It remains rejected as `HirError::UnknownAnnotationInM0` today.

### 2.2 Why (the falsifiable value test fails)

`@transfer` is "structured handoff between agents with confidence scores." The M3.10b bar asks for
a falsifiable value case. For `@transfer` there is **none today**:

- **No consumer** (§0.4): no MCP tool reads it; the 7-agent supervisor routes via external
  `.pipeline/runs/*.json`; the autotuner reads `@strategy`. A confidence-scored handoff *protocol*
  with nothing that acts on the confidence score is speculative infrastructure.
- **No demonstrated producer demand**: unlike FG.3 (whose value rests on the *verified* content-hash
  orphaning of the external log), there is no evidence any agent wants to embed handoff notes in
  `.axc`. Building the protocol would be guessing at a schema for an absent reader — precisely the
  M3.10b anti-pattern.

Contrast with FG.3, which has a concrete, verified weakness it repairs. The pair is intentionally
**split**: build the half with a value case, NO-BUILD the half without one. This is sanctioned
("the milestone may ship as spec+verdict only for that half").

### 2.3 The cheap upgrade path (documented, not taken)

If a consumer appears, the *validate-and-preserve* variant is **~1 schema over FG.3's block
grammar** (a new `"transfer"` HIR arm + a `TransferBlock { confidence_milli: i64 in [0,1000],
target: Ident, message: String }` schema reusing `AnnotationArg::Record`), plus the same
codegen-inert golden gate. This is recorded so the future build is small, but it is **not** built
now because "preserve into a void" delivers only the removal of the reject — no consumer reads it.

### 2.4 Exact revisit trigger

Build `@transfer` — validate-and-preserve first, then the protocol — **when a concrete consumer is
specified**, i.e. either:

1. an **agent-orchestration MCP tool** (an 9th tool, e.g. `next_step`/`route`) is designed to READ a
   kernel's `@transfer` block and drive the next optimization action (which annotation to explore,
   with what confidence), **or**
2. the **7-agent supervisor** is changed to consume in-source `@transfer` handoff instead of (or
   alongside) external `.pipeline/runs/*.json` verdicts.

Until one of those two exists, `@transfer` stays NO-BUILD. (Also naturally revisited alongside FG.9
multi-kernel modules, where cross-kernel handoff acquires a plausible home.)

## 5. Edge cases

- **Float metrics** (e.g. 42.86 TFLOPS) — no float grammar; stored as `metric` (42860) + a
  `unit` ident that carries the ×1000 scale (`mtflops`). Keeps `AnnotationArg` `Int`-only literal
  grammar untouched; `RecordValue` adds no float variant either.
- **Block at capacity / multi-kernel source** — the writer fails closed (`LogOptError::Full` /
  `LogOptError::Multikernel`) and leaves the source byte-unchanged; it can never emit an
  uncompilable file (§1.5).
- **Future-versioned block on an older compiler** — `version:2` with unknown additive keys is
  preserved-and-warned, not rejected (§1.4a); an out-of-v1-range value on a *known* field is still
  rejected by v1 rules.
- **Block on a non-`@kernel` item** — the parser attaches leading annotations to the kernel decl as
  today; a stray block with no `@kernel` follows the existing `has_kernel_annotation` error path.
- **Merge noise / sync drift with the external JSONL** — accepted cost, documented; the two channels
  coexist (embedded = rewrite-surviving, JSONL = machine-run archive); dedup deferred (§1.8).
- **Writer on a syntactically-broken source** — `log-opt` fails closed (parse error surfaced), never
  writes a partial splice.
- **`@transfer` + `@optimization_log` on one kernel** — `@optimization_log` accepted, `@transfer`
  still rejected (UnknownAnnotationInM0); the two decisions compose without interaction.
